# SFC スーパー三國志II ROM 格式

KOEI，1991，SFC。檔案 `roms/Super Sangokushi II (Japan).zip`（Rev 1 的資料表位置與內容相同，差異在程式與部分圖）。

本文的偏移一律是**檔案偏移**（無 copier header 的 1 MB 映像）。CPU 位址寫成 `$bb:aaaa`，LoROM：檔案偏移 = `(bank & 0x7F) × 0x8000 + (addr − 0x8000)`。

這是 FC 版三國志II（`~/works/famicom-re/san2`）的移植。劇本、人物配置、州、相鄰、戰場這些資料表和 FC 版**逐 byte 相同**，只是位置不同（§9 對照表）。欄位意義沿用 FC 版的結論，再用模擬器在 SFC 上重新驗證。

## 1. 硬體與引擎

| 項目 | 內容 |
|------|------|
| 標頭（`0x7FC0`） | `SUPER SANGOKUSHI 2`，map mode `20`（LoROM），型別 `02`（ROM＋RAM＋電池），ROM 1 MB，SRAM 32 KB，版本 0（Rev 1 為 1） |
| 向量 | RESET `$00:800C`；native NMI `$832B`、IRQ `$935B` |
| 引擎 | KOEI p-code 直譯器。取 opcode 的 PC 是 `$00:9AA5`；p-code 讀資料時，Mesen 記到的 PC 是 `$00:006F` |
| 操作 | Y/N 提問：← 是 Y、→ 是 N。數字輸入：↑↓ 改目前位數、←→ 換位數、A 確認；每個提示的第一次按鍵會被吃掉 |

## 2. 檔案表（`0x7800`）

16 bytes 一筆：名稱 8 bytes、bank LE16、位址 LE16、大小 LE32，名稱為 0 時結束。共 34 個檔：`root`、`settei`、`sdata`、`cbmdata1`、`kisetsu`、`comroot`、`excsub1–6`、`csovl1–7`、`hpoint`、`hex`、`hsovl1–6`（含 `51–53`）、`sengo`、`opend`、`endm`。名稱看來是程式 overlay（`*ovl*`、`excsub*`）與資料。`rom.Rom.files()` 讀這張表。

## 3. sdata（`0xFBE0`，`0xDF8E` bytes）：劇本與人物主資料

未壓縮。

| 偏移 | 內容 |
|------|------|
| `0xFBE0` | 4 bytes `4C 03 00 00`（未知） |
| `0xFBE4` | 劇本 6 × 20 bytes：年 LE16（顯示年 − 1：188、193、200、207、214、219 → 189、194、201、208、215、220），其後 18 bytes 未知（看起來是 0–15 的排列） |
| `0xFD1E` | **州**：6 劇本 × 41 州 × 25 bytes（§5） |
| `0x1166C` | 大地圖選州游標的 8 × 9 方格，內容是 0 起算的州號（FC 版相同） |
| `0x11BF4` | **忠誠** 352 × 6：每劇本一 byte，`FF` = 不在場或尚未登場；君主和在野是 `00` |
| `0x12434` | **人物** 352 × 9 bytes（§4.1） |
| `0x13094` | **能力** 352 × 3 bytes：才智、戰力、號召 |
| `0x139EC` | BGR555 調色盤（BG 0–1 等，與 `0x144EC` 前兩組相同） |
| `0x140EC` | 頭像調色盤 4 × 16（§6） |
| `0x1424C` | 大地圖調色盤 16 色（BG 調色盤 7，§7） |
| `0x144EC` | 戰場 BG 調色盤 0–2（§8） |
| `0x146C0` | **姓名** 352 × 15 bytes（§4.2） |
| `0x16FE0` 起 | 訊息文字（半形假名，`0A` 換行，`00` 結尾，夾雜漢字碼） |
| `0x1766C` | **配置** 352 × 22 bytes（§4.3） |
| `0x196A4` | **州相鄰表** 41 × 6（§5） |
| `0x1DA81` | 專屬頭像的調色盤編號，以頭像碼為索引（§6） |

### 4.1 人物（`0x12434`，9 bytes）

| 偏移 | 內容 |
|------|------|
| 0–3 | 義理、人德、野望、相性 |
| 4–5 | 親族 LE16（位元旗標：曹操 1、劉備 2、孫堅 4、袁紹 8 … 公孫瓚 512） |
| 6 | 生年（年齡 = 年 − 生年 + 1；曹操 155 → 189 年 35 歲） |
| 7–8 | 頭像碼 LE16（§6）：< 0x8000 專屬頭像 1–208，≥ 0x8000 組合臉 |

除了頭像碼，這張表和 FC 版相同。才智～相性、親族的數值也和 PC 版人物表（kaodata-re `PERSONS_TABLE/san2_persons.csv`）一致。人物編號順序和 PC 表在 179 號附近開始錯開（SFC 把審榮放在 240）。

### 4.2 姓名（`0x146C0`，15 bytes）

| 偏移 | 內容 |
|------|------|
| 0–6 | 漢字，最多 3 字，每字 2 bytes **大端序的自訂碼**（不是 Shift-JIS，範圍 `81AA–8398`），`00` 結尾 |
| 7–14 | 讀音，cp932 半形片假名，`00` 結尾；8 字時填滿欄位不留結尾（ｼﾞｭﾝｳｹｲ） |

**字型**：碼 X 的字形在 `0x80000 + (X − 0x8000) × 32`，16×16 1bpp，32 bytes 是 4 個 8×8 tile（左上、右上、左下、右下），每個 tile 8 bytes、一 byte 一列、MSB 在左（`rom.Rom.glyph`）。位置是在模擬器裡追蹤畫人名時的 ROM 讀取找到的。

漢字碼對照 `data/kanji_ext.json`（387 字）由 `tools/build_kanji_map.py` 產生：用 PC 版人物表姓名對齊推出，屬外部資料，所以匯出的姓名欄位是 `[EXT]Name`。PC 表的錯誤依讀音或 ROM 字形修正：

- 157 號 ｳｷﾝ 是于禁（PC 表重複了樂進）；淳于瓊落在對齊的空隙裡
- 共用碼 `81D7` 桓、`82D2` 範依多數名字決定
- PC 表把罕用字簡化了，ROM 字形是：阿會**喃**、蔡**瑁**、董**荼**奴、嚴**畯**、劉**璝**、張**顗**（310 號，31 號才是張嶷）

`tools/kanji_sheet.py` 把每個碼的 ROM 字形和指定的字並排畫成 `output/kanji_sheet.png`，387 字逐一目視核對過。ROM 字形用的是新字體（応、楽、国、図、双、当、沢、礼…），對照表保留舊字體。琮、琬各有兩個碼，字形相同。

### 4.3 配置（`0x1766C`，22 bytes，和 FC 版相同）

| 偏移 | 內容 |
|------|------|
| 0 | 登場年（`FF` = 開局就在） |
| 1 | 未知（FC 版也未解） |
| 2–7 | 每劇本所在州（0 起算，`FF` = 不在此劇本） |
| 8–9 | 人物編號 LE16 |
| 10–21 | 每劇本一個 LE16：低 8 bit 是同州串列的下一位（bit 8 在高位元組 bit 0）；高位元組旗標 0x80 君主、0x20 在野、0x10 初期兵 50 |

身分與兵士的推法同 FC 版：忠誠不是 `FF`、或登場年正好是劇本前一年（劇本從前一年 12 月開始）的人才在場；初期兵士君主 100、旗標 0x10 50、其他 10，少數猛將由載入程式另外加到 20／30／50。

和 FC 版唯一的資料差異：審榮（240）在劇本 2 的忠誠，FC 是 `FF`（靠登場年進場），SFC 直接給 85。

劇本載入後，WRAM 裡每人是 21 bytes（結構同 FC）：`+0` 同州下一位的指標、`+4..6` 知武魅、`+7` 所屬勢力、`+8` 忠誠、`+12` 兵士 LE16、`+14` 兵士 × 10、`+16` 訓練、`+19` 人物編號 LE16。

## 5. 州（41 州）

**劇本州資料** `0xFD1E + 1025 × 劇本`，每劇本 41 × 25 bytes。劇本載入時整段複製到 WRAM `$7E:F422`。

| 偏移 | 內容 |
|------|------|
| 0–7 | 執行期指標（人物串列） |
| 8、10、12 | 金、兵糧、人口（LE16） |
| 14 | 勢力（`FF` = 空白州） |
| 15–19 | 執行期（16–17 載入後會被改寫） |
| 20–24 | 土地、民忠、治水、馬、信（畫面標「信」，ROM 裡全部是 50） |

欄位對照遊戲畫面確認：劇本 1 開局的揚州-24（王朗）畫面是人口 3500、金 1000、兵糧 250、民 50、土 55、水 30、信 50、馬 10，ROM 是 `+20` 55、`+21` 50。所以 `+20` 是土地、`+21` 是民忠。FC 版文件寫成「+20 民忠、+21 土地、+24 相場」，它對照的荊州-19 民、土剛好都是 50，分不出順序。畫面的「相」（相場）每次看都不同（52、44、32），是執行期的值；「兵士」110 是州內人物兵士合計，「武」「在」是人數。

**相鄰表** `0x196A4`：41 × 6 bytes，1 起算，`FF` = 沒有相鄰州。slot 位置就是六角方向：j 在 i 的 slot d，i 就在 j 的 slot 5 − d。41 州、93 條邊可以完整放上六角格（`Rom.hex_layout`，圖見 `output/province_hex.png`）。

## 6. 頭像

40 × 48 = 5 × 6 個 4bpp tile，以列為主序，每張 960 bytes。

**專屬頭像**（碼 1–208）：

- tile 在 `0x90000 + (i ÷ 34) × 0x8000 + (i mod 34) × 960`，i = 碼 − 1。一個 bank 放 34 張，不跨 bank。
- 調色盤編號（0–3）是 `0x1DA81 + 碼` 的 byte。

**組合臉**（碼 bit 15 = 1）：

- bit 0–2 是頭型。頭型 h 的資料在 `0xC8000 + h × 0xF00`，共 4 筆記錄 × 960 bytes。
- 每個區域用 2 bit 選記錄：上（bit 3–4）、下（5–6）、眼（7–8）、鼻（9–10）、口（11–12）。bit 13–14 是調色盤。
- 部件表 `0xCDF2`：8 頭型 × 6 bytes，依序是眼、鼻、口的起始欄，再來是三者的寬度。眼、鼻、口各在第 2、3、4 列。
- 「上」與「下」是部件以外、分界列上方與下方的格子。分界列是第 3 列，頭型 3 例外，是第 2 列。這是從遊戲的讀取順序看出來的，沒有找到表。

**調色盤**：4 組 × 16 色 BGR555，在 `0x140EC`，遊戲載入到 CGRAM 調色盤 8–11。8-bit 換算為 `(v << 3) | (v >> 2)`，和 Mesen 一致。

驗證：`verify_kaodata_export.py` 在模擬器裡把王朗的頭像碼換成每個人實際用到的 352 個碼，讀畫面像素比對，352/352 相符。

## 7. 大地圖

- 一張 28 × 18 tile 的點陣圖，tile 在 `0x88000`（504 個 4bpp tile，以列為主序），用 BG 調色盤 7（`0x1424C`）。
- 遊戲把它載入 VRAM tile `0x1D0` 起，BG1 tilemap 從 (2, 3) 依序排列。
- 州號已經畫在圖上。勢力色是執行期把州內的顏色 7（白）改成 8–15 畫上去的，ROM 裡的是未上色的原圖。
- 遊戲怎麼知道哪些像素屬於哪一州（填色範圍）尚未解。

## 8. 戰場地圖

- `0x322D4`（檔案 `hpoint` 內）：41 張 × 78 bytes，每張 13 欄 × 12 列六角格，每格 4 bit（高 nibble 在前），以列為主序。
- 地形 id 沿用 FC 版的命名：0 平地、1 森、2 林、3 山、4 河、5 村、6 城。
- 開戰時遊戲只讀一張圖：袁術攻打劉表的州 20，讀的是 `$06:A89E` = `0x322D4 + 78 × 19`。
- **畫面**：每格六角占 2 × 2 tile，第 c 欄、第 r 列的左上角在 BG1 tilemap (3 + 2c, 3 + 2r + c mod 2)，奇數欄往下錯開 1 tile。BG1 vscroll 是 4。
- **地形 tile 表** `0x33370`：7 地形 × 4 個 tilemap entry（LE16，左上、右上、左下、右下），含調色盤欄位。用到 VRAM tile `0x1C0–0x1DB`。
- **tile 圖**：
  - `0x1C0–0x1CF`（平地～山）在 `0xD31C0` 起依序排列。
  - `0x1D4–0x1DB`（村、城）接在 `0xD33C0`。
  - 河 `0x1D0–0x1D3` 是動畫：tile n 的第 j 格（j = 0–3）在 `0xD34C0 + 32 × (4n + j)`。匯出用第 0 格。
- **調色盤**：BG 調色盤 0–2 在 `0x144EC`。
- 進軍點標記：攻方的 5 個進場格，遊戲會把右上角的 tile 換成 `0x1F3`（白圈）。這 5 格在 hex 11、12、24、25、38，也就是第 0 列第 11、12 欄、第 1 列第 11、12 欄、第 2 列第 12 欄（右上角）。這是從州 19 進攻時的位置，換別的方向進攻是否會變沒有測。
- 開戰時另外讀了 `0x31C20` 起的 156 bytes。它在 `0x31914` 那張 13 × 12 nibble 圖之後 780 bytes 處，那張圖和 FC 版 `0x28BE4` 相同，推測是佈陣範本，尚未解。

全中國戰場拼接：資料與 FC 版相同，所以沿用 FC 版的「直欄」排法（`famicom-re/san2/docs/ROM_FORMAT.md`〈全中國戰場拼接測試〉）。`output/china_battle_map.png` 裡，河流與地形都跨接縫接起來。
