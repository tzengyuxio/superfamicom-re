# SFC 三國志英傑伝 ROM 格式

KOEI，1995，SFC。檔案 `roms/Sangokushi Eiketsuden (Japan).zip`。

本文的偏移一律是**檔案偏移**（沒有 copier header 的 3 MB 映像）。CPU 位址寫成 `$bb:aaaa`。HiROM 的換算是：檔案偏移 = `位址 & 0x3FFFFF`（`$C0:0000` = 檔案 0）。標「推測」的地方沒有經過獨立驗證。

## 1. 硬體與引擎

| 項目 | 內容 |
|------|------|
| 標頭（`0xFFC0`） | `EIKETSUDEN`，map mode `31`（HiROM），SRAM 32 KB |
| 向量 | native NMI 是 `$00:8FC3` |
| 函式呼叫 | 透過 `JSL $C0:8003`（函式號＋堆疊引數）分派。`0x0E` 是解壓：A = 來源 bank，堆疊上先放來源、再放目的地，目的地固定在 `$7F` |
| 指標表 | 每項 **4 bytes**（3-byte 長指標＋`00`），一般放在資料後面 |
| 劇本腳本 | 沒有壓縮的 bytecode，一章用一個 bank（序章在 `0xB0000`，開頭是 LE16 子區塊偏移表；第一章 `0xD0000`、第二章 `0xE0000`）。取 opcode 的程式是 `$C6:AD20`（byte）和 `$C6:AD45`（word），各 opcode 的處理程式在 `$C4:1E00–$C4:4400` |

**操作序列**（從開機算幀數，按鍵按住 10 幀；寫成 `tools/drive.py` 的語法，`eiketsu/tools/replay.py` 裡有定義）：

- 進幕舎：`w1200 start:10 w300 a:10 w300` ＋ 78 次 `a:10 w200` ＋ `w200`。開場劇情播完以後，約第 20000 幀可以在劉備的幕舎自由走動。
- 第一場戰鬥：`down:3 w20 left:3 w20` 走到関羽旁邊，按 8 次 `a:10 w100`（對話、選「出陣」、一次存檔確認），再按 5 次 `a:10 w150`。第 21676 幀那一下會開始汜水関之戰，第 21750 幀左右載入地圖。按到第 6 次時，華雄開口說話，頭像在第 22450 幀左右建好。
- 環狀選單：按 X 打開，上 = 情報，左 = 全体図，右 = 道具，下 = 機能。情報裡選左 = 武将表，在表上按 a 看狀態畫面，按 R 換頁（武力 統率 知力 経験）。

用 Mesen 驗證時，savestate 只能在 exec callback 裡建立或載入，所以掛在 NMI handler 上。建立和載入不能放在同一個 callback 呼叫裡（會出現 “must be called inside an exec memory operation callback”），要等下一次 NMI 再載入。載入後的第一輪不可靠，所以第一項跑兩次，丟掉第一次的結果。

## 2. 壓縮資料

KOEI 的 LZ，表在 `0xF037`，解壓程式在 `$C0:F194`，和天翔記、三國志IV 是同一套，直接用共用的 `tools/koei_lz.py`。

## 3. 字型與文字

- **文字**：漢字用 Shift-JIS（cp932），讀音用半形片假名。劇情對話裡的假名是另一套 1-byte 自訂碼（例如 の = `0x4D`），這套碼還沒整理。
- **字型**：字碼表在 `0x9CA1D`，是 1655 個遞增的 LE16 Shift-JIS 碼。字號就是碼在表中的位置，`$C1:0878` 用二分搜尋查表：碼放在堆疊 sp+4，結果放在 DP `$00`。字形在 `0x220EC + 32 × 字號`，16 × 16 1bpp，逐列存放，每列 2 bytes（左半、右半）。`$C9:9371` 算出字形位址，再交給 `$C1:08B0` 轉成畫面用的格式（帶陰影的 2bpp，送到 `$7E:F37A`）。
- **外字**：使用者外字區 `0xEB9F–0xEBE7`，共 37 個，是字型的最後 37 個字形（1618–1654）。依字形和用到它的名字判斷，對照表在 `data/ext_chars.txt`，`rom.EXT_CHARS` 從這個檔讀入：

  瓚 昱 彧 郃 蒯 蔡 傕 汜 詡 鄧 兗 龐 騭 畯 闞 玠 邢 禕 琬 郝 邳 琦 琮 璝 褚 邳（`EBCC`，字形與 `EBBF` 相同）宛 釭 鄴 雒 涪 邈 潁 鑲（鉤鑲）牀（三弓牀子弩）焔（火焔斧）

  `EBD5` 沒有名字用到，字形像「慕」，暫列未辨識。輸出時，未辨識的外字寫成 `[EBD5]`。

## 4. 主表（`0x8EBA0`：8 個 4-byte 指標）

| # | 位置 | 內容 |
|---|------|------|
| 0 | `0x8CEA4` | 73 bytes，沒有壓縮，未解 |
| 1–4 | LZ | 地點列表 1–4（§7） |
| 5 | LZ | NPC 類型 256 筆 × 9 bytes：名稱 8 bytes（老人、男の子、農民、宮使い…）＋ 1 byte（0 或 17–28，未解，推測是地圖上的人物圖編號） |
| 6 | LZ | 人物名稱表 384 × 16 bytes（§5） |
| 7 | LZ | 人物能力表 384 × 19 bytes（§5） |

## 5. 人物（384 人）

**名稱表**（主表 #6，16 bytes）：

| 偏移 | 內容 |
|------|------|
| +0–5 | 姓名（cp932＋外字，NUL 結尾，NUL 後面可能有殘留的 byte） |
| +6–13 | 讀音（半形片假名） |
| +14 | 頭像號 0–239（§8）。劉備 0、関羽 1、張飛 2、華雄 138 |
| +15 | 未解，值 0–28。推測是地圖上的人物圖，與 NPC 表的值域相同 |

**能力表**（主表 #7，19 bytes）：

| 偏移 | 內容 |
|------|------|
| +0 | bit 7 一律是 1；低 7 位是勢力 0–14（§6）。劉備軍 0、董卓 5；依名字對照，推測 |
| +1 | 武力 |
| +2 | 統率 |
| +3 | 知力 |
| +4–5 | LE16，未解（`0x460`、`0x5A0`、`0x6E0`…；不是耐久） |
| +6 | 未解（0–5），執行中的紀錄存成這個值 + 2 |
| +7 | 兵種（§6）。劉備 0 = 短兵，関羽、張飛 6 = 軽騎兵 |
| +8 | 等級。劉備 1；敵將出場時，腳本會再加值（汜水関的華雄 3 → 7） |
| +9 | 0 |
| +10–17 | 持有道具 8 格（§6，`FF` = 空）。関羽 12 青龍偃月刀、張飛 15 蛇矛、呂布 7 赤兎馬 ＋ 14 方天画戟 |
| +18 | 0 |

**執行中的人物表**：新遊戲開始時（約第 1566 幀），`$C8:0D39` 在 `$7E:200D` 建出 384 筆、每筆 43 bytes 的紀錄，第 k 筆就是人物 k。各欄位如下：

| 偏移 | 內容 |
|------|------|
| +0–1 | 狀態（`02 00`） |
| +4 | 未解 |
| +5–10 | 姓名 |
| +12–19 | 讀音 |
| +21 | 頭像 |
| +23 | 能力 +0 |
| +24–26 | 武力、統率、知力 |
| +27–28 | 耐久 LE16（劉備 250；從哪裡算出來的未解） |
| +29 | 能力 +6，再加 2 |
| +30 | 兵種 |
| +31 | 等級 |
| +32 | 能力 +9 |
| +33–40 | 道具 |
| +41 | 能力 +18 |
| +42 | 人物號 + 1 |

狀態畫面的攻撃、防御、策略由兵種係數算出（§6）。劉備是 攻撃 92、防御 114、策略 20；関羽是 123、120、15。

## 7. 地點與大地圖（全体図）

**地點列表**（主表 #1–4，每組 32 筆 × 21 bytes）：名稱 8 bytes、讀音 12 bytes、種類 1 byte。種類的值有 0、2（関）、3（推測是城）、4（推測是庵或村：孔明庵、隆中、古城、来陽県）。沒用到的格子填「渡哲也」。

**大地圖**：

- tile：LZ 串流 `0x1E0000`（`$DE:0000`），共 513 個 4bpp tile，放在 VRAM tile 64（word `0x0400`）。
- tilemap：LZ 串流 `0x1E35DE`，32 × 28 個 LE16 BG entry，放在 VRAM word `0x3800`。
- 調色盤：`0x4E653`，0x60 bytes，載到 CGRAM 調色盤 4–6。

**地點標記**：

- 畫在另一層 BG（VRAM word `0x3C00`），格 (x, y) 寫入 entry `0x3E41`（來源 `0x4E6B3`），由 `$C8:890A` 讀座標。
- 座標表在 `0x9C6EB`，每筆 2 bytes (x, y)，`FF FF` 表示沒有標記。
- 地點列表 g 的第 i 筆用座標表的第 `start[g] + i` 筆，條件是 i < `count[g]`。`count` 在 `0x9C5F7`（22 16 26 14），`start` 在 `0x9C5FC`（0 22 38 64）。
- 章號（`$7E:7618`）決定顯示哪一組：`0x37B4A` 的表把章 0–4 對到組 0 0 1 2 3，也就是列表 1 1 2 3 4。

`0x9C600–0x9C6EA` 還有一張 byte 對的表，未解，推測是城鎮或幕舎的座標。

## 8. 頭像（240 張）

- 每張 48 × 48，也就是 6 × 6 個 4bpp tile 逐列排，1152 bytes，每張一個 LZ 串流。
- 頭像程式 `$C7:04F7`（引數 = 堆疊 sp+4 的頭像號）依頭像號選指標表：

  | 頭像號 | 指標表 |
  |--------|--------|
  | < 72 | `0x11F7BC` |
  | < 144 | `0x12FB78` |
  | < 216 | `0x13FD1E` |
  | < 240 | `0x14492F` |
  | 其他 | 頭像 0 |

- 解壓後複製到 `$7E:8444`，戰鬥對話時再送到 VRAM byte `0x5F40`。`$7E:88C4` 記住上一次的頭像號，號碼相同時直接跳過。
- 調色盤：所有頭像共用 CGRAM 調色盤 3 = `0x4DE05`（32 bytes）。

這個遊戲沒有組合臉。人物頭像號見 §5，多名人物可以共用同一張頭像。

## 9. 戰鬥與戰場地圖（58 場）

- **開始戰鬥**：腳本 op `09` 帶一個 word，寫到 `$7E:7624`。`0x1000` 是幕舎，`0x2000` 是城鎮，`0x3000 + n` 是第 n 場戰鬥。`$C5:CBBF` 把 n 複製到 `$7E:D979`（從 `$C5:9230` 呼叫）。序章第一場戰鬥的參數在 `$CB:076A`（檔案 `0xB076A`，`00 30`）。
- **地圖**：第 n 場用 `0x1F45E` 指標表的第 n 個串流（`$C5:8DFD` 讀取）。
  - 串流格式：W、H（以 16 × 16 方塊計），接著 W × H 個方塊號，再接 (W/2) × (H/2) 個地形 byte。地形格是 32 × 32 px，值是地形名（§6）的索引。
  - 地圖大小從 32 × 40 到 80 × 48 方塊不等。地形 byte 只出現過一次 `FF`。
  - 地形值和畫面對得上（汜水関：9 崖、1 林、3 川、4 橋、5 城壁、7 草原、11 荒地、13 砦、15 兵糧庫），但遊戲顯示地形名的地方沒有追蹤，所以地形名稱的對應算推測。
  - 載入後，地形格放在 `$7F:C910`。
- **名稱**：`0x5D4EB` 有 58 個 4-byte 指標。字尾「の戦い」在 `0x5D71D`。遊戲把標題組在 `$7E:D97F`，結尾是 Ⅰ–Ⅱ–Ⅲ 的名字，「の戦い」插在數字前面（宛Ⅰ → 宛の戦いⅠ）。
- **圖塊組**：`0x5D4C5` 有 19 個 LE16 地圖號（0 1 4 8 10 16 20 28 29 30 35 36 39 40 42 43 44 50 52），在這份清單裡的地圖用第 1 組，其他用第 0 組（`$C5:CC2F`、`$C6:7BFF`）。指標表 `0x1CACD1` 有 9 項：
  - [組] = 4bpp tile，放在 VRAM tile 64；第 0 組 659 個，第 1 組 666 個。
  - [2 + 組] = 方塊表，256 個方塊 × 4 個 LE16 BG entry（左上、右上、左下、右下）；方塊 255 沒有用到。
  - [4 + 組] = 1024 bytes，解到 `$7F:5340`，未解，看起來是圖形。
  - [6–8] = 3 塊 64 bytes 的原始資料，沒有壓縮，未解。
- **調色盤**：4–6 號在第 0 組用 `0x1CACF5`、第 1 組用 `0x1CAD55`（各 0x60 bytes，`$C7:142B`）。調色盤 7 用 `0x1CADB5`。地圖本身只用到調色盤 4–6。
- **BG**：tilemap 在 VRAM word `0x3800`（64 × 32），每幀從 `$7F:0000` 把鏡頭附近的一塊送過去。
- **敵方配置**：放在腳本的戰鬥區塊裡。格式只解出一部分：序章 `0xB05E4` 的 byte 是華雄的等級加值（改成 0 後，華雄是 Lv3）。

## 10. 未解

- 劇本腳本的 opcode 表、劇情對話的假名碼、敵我配置與勝利條件的完整格式（汜水関的勝利條件「『華雄』の壊滅」和 30 回合限制在 `$7E:79D0` 一帶），以及章的劃分（目前只確認 `$7E:7618` 是章號）。
- 人物：名稱 +15、能力 +4–5、+6；耐久、攻撃、防御的公式；執行中紀錄 +4 的意義。勢力 byte 的意義還沒有在遊戲畫面上確認。
- 道具 +15–19，以及效果號的對應。
- 主表 #0、NPC 表的第 9 byte、地點種類 0 和 4 的確切意義。
- 戰場圖塊組的 [4–8] 項、`0x1CCE65` 的 13 個串流、各兵種的移動與相剋表（`0x37CE6` 以後）。
- 城鎮與幕舎地圖（`0x8C930` 指向的 8192 bytes 串流，推測是方塊地圖）。
- 外字 `EBD5`。
