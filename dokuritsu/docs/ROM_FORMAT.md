# SFC 独立戦争 Liberty or Death ROM 格式

KOEI，1994，SFC。檔案 `roms/Dokuritsu Sensou - Liberty or Death (Japan).zip`。

本文的偏移一律是**檔案偏移**（無 copier header 的 1.25 MB 映像）。CPU 位址寫成 `$bb:aaaa`，HiROM：檔案偏移 = `位址 & 0x3FFFFF`（`$C0:0000` = 檔案 0）。「推測」表示沒有獨立驗證過，「未解」表示意思不明、只輸出原始值。

## 1. 硬體與引擎

| 項目 | 內容 |
|------|------|
| 標頭（`0xFFC0`） | `DokuritsuSensou`，map mode `31`（HiROM），SRAM 8 KB |
| 向量 | native NMI `$00:848D`（savestate 掛在 `$00:848E`） |
| 程式 | C 編譯：引數放堆疊、`$00`–`$0E` 當暫存器、算術走函式（`$C1:F2F5` 乘法、`$C1:F40D`／`$C1:F532` 無號除／餘、`$C1:F763` 有號 ≥ 等） |
| 共用服務 | `JSL $C0:8000`，引數複製到 `$52`，`$52` = 服務號，跳轉表 `$C0:9727`。`0x17` memcpy（經 `$00:006C` 的 MVN）、`0x4C` LZ 解壓（目的、來源長指標）、`0x0B`／`0x0D` 上傳 VRAM、`0x03` 調色盤 DMA |
| printf | `$C1:430F` 是 vprintf（格式長指標在 SP+4，va 指標在 SP+8；`%s` 取 3 bytes 指標、`%d` 取 2 bytes）；`$C1:527C(fmt, …)` 印到視窗，`$C1:214E(x, y)` 設游標。**驗證幾乎都靠掛這個函式讀引數** |

## 2. 壓縮資料

KOEI 的 LZ，表在 `0xA0D9`（和覇王伝同一套），直接用共用的 `tools/koei_lz.py`。長指標表 `0x39649`（`$C3:9649`），419 筆，本文稱「LZ entry i」。

| entry | 內容 |
|-------|------|
| 1 | HEX 戰場層 A：16 bytes 標頭 `LIBERTY_HEX_MAP\0` ＋ 53 × 336 bytes |
| 2 | HEX 戰場層 B：53 × 336 bytes |
| 16–18 | 大地圖 北部／中部／南部，各 672 個 4bpp tile |
| 67–240 | 頭像 0–173，每張 960 bytes |
| 241 | 戰場地形 tile（71 個，放到 VRAM tile `0x2B9`） |

## 3. 文字

- 半形假名＝cp932 單 byte。`1B 4B`（ESC K）切片假名、`1B 48`（ESC H）切平假名：同一組 byte 在平假名模式讀成平假名。`1B 43 n` 設顏色。
- `0x81`–`0x83` 開頭的 2 bytes 是漢字，**順序是遊戲自訂的**（不是 JIS）。字型沒找到（推測在別處壓縮或在 RAM 組字），只從畫面對出 10 個：統 `832F`、率 `83D0`、力 `83DC`、戦 `82C0`、術 `826F`、指 `8241`、導 `8336`、名 `83A7`、声 `82AD`、軍 `81DF`（`rom.KANJI`）。其他輸出成 `{XXXX}`。
- 人名、地名都只用假名（人名之外另有 ASCII 首字母，見 §4）。

## 4. 人物（`0x1A7F7`，250 筆 × 33 bytes，依姓排序）

讀取函式 `$C8:0BFD(id)` = `$C1:A7F7 + 33 id`。

| 偏移 | 內容 |
|------|------|
| +0 | 名的首字母（ASCII）、+1 = 0。人物列表顯示成「G.ワシントン」 |
| +2–13 | 名（半形片假名） |
| +14–24 | 姓 |
| +25 | 体力（開局值；168/250 人和人物狀態 +3 相同） |
| +26 | 統率力 |
| +27 | 戦術力 |
| +28 | 指導力 |
| +29 | bit 0–1：種別 0–3（未解）；bit 2–7：多數是 63，少數人（バトラー、ジョンソン、アレン、ギャンブル）是小數值，未解 |
| +30 | 未解（多數是 53） |
| +31–32 | 頭像碼 LE16（§8） |

ジョージ・ワシントン = 238（統率力 97 戦術力 88 指導力 98，頭像 117），トーマス・ゲージ = 82（頭像 34）。

## 5. 地點（`0x19178`，53 筆 × 25 bytes）

讀取函式 `$C8:0BA3(id)`。遊戲顯示的編號是 id + 1。

| 偏移 | 內容 |
|------|------|
| +0 | 0–100，未解（ロングアイランド 100、ボストン 73） |
| +1 | 旗標，未解 |
| +2–15 | 名稱 |
| +16–23 | 相鄰地點 8 個，`FF` 補滿 |
| +24 | bit 0–1：地區（0 北部、1 中部、2 南部）；bit 2–5：州（§6）；bit 6：港（推測，海岸的地點才有） |

## 6. 州（15 個）

略稱：長指標表 `0x1D372`（15 × 3 bytes）→ `MA CD NH NY RI CT NJ PA DE MD VA NC SC GA FL`。全名：長指標表 `0x1D3CC`，例如 `マサチューセッツ`；CD、FL 前面是兩個漢字 `{8162}{83DB}`（推測「英領」：英領カナダ、英領フロリダ）。

## 7. 1775 年劇本（只有一個）

選「新しく始める」時 `$C8:17FC` 把下列 ROM 原封複製到 WRAM（第 10172 幀比對 0 byte 不同）：

| ROM | WRAM | 長度 | 內容 |
|-----|------|------|------|
| `0x18D7C` | `$7E:2009` | `0x47` | 未解（`ff 35 00 01 … 34 ff 74 a6 …`） |
| `0x18DC3` | `$7E:2054` | `0x41` | 13 × 5 bytes，未解 |
| `0x18E04` | `$7E:2095` | `0x2E6` | 地點狀態 53 × 14 |
| `0x190EA` | `$7E:237B` | `0x2C` | 2 × 22 bytes（每陣營 20 個 70），未解；`$C8:0C2C(id)` = `$237B + id` |
| `0x19116` | `$7E:23A7` | `0x62` | 陣營 2 × 49 |
| `0x19A4B` | `$7E:2409` | `0xDAC` | 人物狀態 250 × 14 |

之後還設 `$2050`／`$2052` = 0、`$31B5` = 0 並呼叫 `$C9:00F8`。選完陣營後遊戲改寫少數欄位：`$23A7` = `0x310D`（ワシントン的狀態指標）、`$23D8` = `0x2885`（ゲージ）、`$23AB` = 1、`$204F` = 1，指揮官的人物狀態 +7 旗標、ボストン一帶的人物串列。

### 人物狀態（`$7E:2409 + 14 id`）

| 偏移 | 內容 |
|------|------|
| +0–1 | 同一串列的下一人（WRAM 指標，0 結尾） |
| +2 | 所在地點，`0x35` = 不在地點（待機） |
| +3 | 体力 |
| +4 | 名声 |
| +5 | 忠誠（指揮官顯示 `---`） |
| +6 | 高 4 位元：所屬（推測：0 大陸軍、1 民兵、2 フランス、3 スペイン、4 イギリス、5 王党派・インディアン）；低 4 位元未解 |
| +7 | bit 0–1：階級（推測）；`0x20`／`0x40`／`0x80` 旗標未解 |
| +8–13 | 未解（+9 常見 0／60／80／208／63，+10 常見 `FA`／`7D`） |

`$C8:0BD2(id)` 回傳指標，`$C8:0ACD(指標)` 回傳 id。

### 地點狀態（`$7E:2095 + 14 id`）

| 偏移 | 內容 |
|------|------|
| +0–1、+2–3 | 人物串列的頭（WRAM 指標；開局兩個相同；+0 是人物列表畫面用的那個） |
| +4 | 擁有者代碼 0／1／4／5／6，未解 |
| +5 | 支持（豎拇指圖示） |
| +6–7 | 食糧（麵包圖示） |
| +8–9 | 炸彈圖示：武器（推測） |
| +10–11 | 火藥袋圖示：弾薬（推測） |
| +12 | 100，未解 |

指令畫面左上的大數字（例如 972）與「2-2」是計算值，不在表裡。

### 陣營（`$7E:23A7 + 49 id`，0 アメリカ、1 イギリス）

| 偏移 | 內容 |
|------|------|
| +0–1 | 指揮官（人物狀態指標，選完陣營才設） |
| +2–3 | 待機人物串列的頭（アメリカ 100 人、イギリス 95 人） |
| +5–6 | 500（推測：資金） |
| 其餘 | 0 |

## 8. 頭像

40 × 48 = 5 × 6 個 4bpp tile，逐列排列（960 bytes），由 `$C2:3FA8` 畫。全部用同一組調色盤 `0x39B72`（畫面上的 CGRAM 調色盤 2）。

- **專屬**（碼 bit 15 = 0）：LZ entry `67 + 碼`。共 174 張（0–173），人物只用到 0–124。
- **組合**（bit 15 = 1，`$C2:3E66`／`$C2:3ADA`）：把碼拆成 6 個 2-bit 數字 d0–d5（d0 = bit 10–11 … d5 = bit 0–1）。d0 = 型 t（0–3）。遊戲依序畫 k = 5、1、2、3、4，第 k 次畫部件 p = k − 1 的第 d[k] 個變體。
  - 部件資料**沒有壓縮**，從檔案偏移 0 開始，依 [型][部件] 排：每個 (t, p) 有 4 個變體 × T[t][p] 個 tile × 32 bytes。T 是 `0x18D35` 的 LE16 表：型 0 = 25 3 3 1 10，型 1、2 = 20 3 2 3 10，型 3 = 20 2 2 2 10。
  - 大小表 `0x2F811`（LE16，10 × 欄 + 列）、位置表 `0x2F839`（LE16，10 × x + y）。部件第 r 列寫到臉的 tile (r + y) × 5 + x 起。
  - 例外：型 0 的部件 0 只畫 列 − 1 列，接著把下一個來源 tile 放到 (y + 4, x)、再隔 4 個 tile 的那個放到 (y + 4, x + 4)。
  - 部件 4 = 下 2 列（先畫）、部件 0 = 上 4 列、部件 1／2／3 = 第 3／4／5 列；4 型都蓋滿 30 個 tile。遊戲把部件偏移暫存在 `$7E:31B7`。
  - 人物用到 125 種組合碼。

## 9. 大地圖

BG2（mode 1）：tilemap VRAM `0xC800`、chr 0，調色盤 3 = ROM `0x39C52`。地圖畫面分 3 區，各是 LZ entry 16／17／18（北部／中部／南部），672 個 tile 放在 VRAM tile 8 起，在 tilemap 的第 2 列第 2 欄起排成連續的 28 × 24 塊（224 × 192 px），entry = `0x0C00 | 8 + 28 列 + 欄`。地點編號直接畫在圖裡。

遊戲執行時另外：
- 把北部的 100 個外海格換成動畫 tile 4–7；
- 調色盤 3 的顏色 9–11（水）循環；
- 依擁有者把各地點的陸地顏色 15（白）改成 3、8、12（紅、藍、綠一類；對應哪個陣營推測），以每區的遮罩決定像素，遮罩**未解**。匯出的地圖是上色前的白底。

## 10. HEX 戰場地圖（53 張，每地點一張）

戰鬥載入時 `$C1:7A44`／`$C1:7ABD` 以 `$C8:0AA0($7E:2050)`（地點 id）為編號，把層 A／B 複製到 `$7E:4363`／`$7E:44B3`。

- 14 欄 × 12 列的六角格，每格 2 bytes，逐列排列；每張 336 bytes。
- **層 A**（entry 1，跳過 16 bytes 標頭）：byte 0 低 4 位元 = 地形 0–10，高 4 位元與 byte 1 未解（`0x10`／`0x20`／`0x40`／`0x80`、`0x00`／`0x10`／`0x20`／`0x40`）。
- **層 B**（entry 2）：LE16。地形 4、5、7 的格若不是 `8888`，4 個 nibble 就是 4 個 tile 的編號（左上、右上、左下、右下，低位先）；`8888` = 用一般 tile，`FFFF` = 無（其他地形）。
- BG2 tilemap 由 `$C6:6CAB` 在 `$7F:8000`（32 × 28）建好再上傳 VRAM `0xC000`：
  - 格 (x, y) 佔 tile 欄 2x + 2、列 2y + 2 +（x 偶數時 1）起的 2 × 2（`$C6:2A94`）；
  - 一般 tile：`0x1B9 + 4 地形 + k`；疊加 tile：地形 7 → `0x1E5`、4 → `0x1EE`、5 → `0x1F7`，再加 nibble（`$C6:6AFF`、`$C6:2DEC`）；
  - 最後整張 + `0x100`（`$C6:6D27`），所以實際是 tile `0x2B9` 起 = LZ entry 241（`$C6:2578` 載入 71 個 tile）；格子用調色盤 5 = ROM `0x39DD2`（1775 年那場；季節是否換色未查），地圖外圍大致以夾在邊界的格子補滿（調色盤 6，少數邊緣 tile 不同，未細查）。
- 地形外觀（看 tile 判斷，名稱推測）：0 草地、1 森林、2 丘陵、3 山、4 河川、5 淺灘、6 未使用、7 海・湖、8 城鎮、9 要塞、10 柵欄陣地。

## 11. 操作序列（tools/drive.py 語法）

| 目的 | 序列 |
|------|------|
| 開頭動畫跳不掉；標題約第 10000 幀 | `w9800 start:10` |
| 人類操作アメリカ → 選陣營畫面（ワシントン，約第 10870 幀畫好） | `w9800 start:10 w200 a:10 w200 a:10 w200 a:10 w200 a:10 w300`（start 後第一個 a 常被吃掉） |
| 到第一個指令畫面（約第 22200 幀） | `verify_scenarios.MAIN` |
| 指令畫面 → 軍事 → 人物列表 | `a:10 w100 down:10 w100 a:10 w200 a:10 w200 down:10 w100 a:10 w200` |
| 兩邊都電腦、HEX戦 見る；第一場戰鬥（ポーツマス）約第 16600 幀載入 | `verify_battle_maps.BOOT` |

主選單是 内政、物資、人事、軍事、情報；人物列表顯示 体力、忠誠、名声。

## 12. 未解

- 漢字字型與完整字碼表（只對出 10 字）。
- 人物 +29（bit 2–7）、+30；人物狀態 +6 低位、+7 旗標、+8–13；所屬與階級只是推測。
- 地點 +0、+1；地點狀態 +4（擁有者代碼）、+12；武器／弾薬的區分是看圖示推測。
- WRAM `$2009`、`$2054`、`$237B` 三塊的意義；陣營 +5 是否為資金。
- 大地圖的擁有者上色遮罩、外海動畫格位置表、地點在圖上的座標。
- 戰場層 A 的高位元與 byte 1、地形名稱、戰場用的部隊與兵種資料；季節調色盤。
