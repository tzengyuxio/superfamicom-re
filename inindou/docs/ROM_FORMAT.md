# スーパー伊忍道 打倒信長（SFC）ROM 格式

位址是無標頭 1.25 MB LoROM 影像（0x140000）的檔案位移：`$bb:aaaa` → `bb × 0x8000 + (aaaa & 0x7FFF)`。
標頭 `SUPER ININDOU`，map 0x20，type 02，SRAM 8 KB。native NMI 向量 `$00:8355`（`tools/replay.py` 掛在 `$8356`），reset `$8000`。

遊戲主體是 p-code 直譯器：p-code 與資料的讀取都在 PC `$00:006F`（所以讀取追蹤看到的 PC 幾乎都是 006F）。沒有 KOEI LZ。
標「推定」的是沒有用遊戲程式驗證過的解讀；標「未解」的是還不知道。各項的驗證方式見 `README.md`。

## 檔案系統

`0x7800` 起每筆 16 bytes：`[名稱 8][bank LE16][位址 LE16][大小 LE32]`，名稱第一個 byte 是 0 就結束，共 67 個檔。
`0xB248` 起另有 overlay 名稱＋載入位址表（如 `iovl → $6000`、`novl → $8800`、`covl1–7 → $C000`、`mmovl0–9 → $A400/$AF00`）。

| kpdata | 0xB85A | 0xF94 | 未解 |

| rjdata | 0xD792 | 0x1ABC | 敵人 180 筆 |

美版（Inindo - Way of the Ninja）檔案系統同格式，多了 km1ovl–km5ovl，沒有 msg/dmsg。美版只用來對照英文名稱：

依 23 bytes 資料比對出英文名（136 筆對上）。

## 文字與字型

- 字碼 2 bytes big-endian，字形 g = 碼 − 0x8132（`0x8141` = 「、」），字串以 0 結束。
- 低位 byte 是 0 的碼放不進字串，用跳脫碼：`0x89F0 + k` 代表 `0x8200 + 0x100 k`（k = 0–5：ピ 供 慈 装 般 歴）。
  人物 23「般若王」就是 `89F4 8EE2 8996`（畫面確認）。ヨーロッパ戦線 的 `$C1:19C0` 也是同一套換算。
- 小於 0x80 的單一 byte 是單 byte 碼；只看到術名「錯乱」中間的 `20 20`（兩個半形空白），`rom.py` 照單 byte 處理並在術名裡去掉。
- 字型 `0x88000`，16×16 1bpp，每字 32 bytes（左上、右上、左下、右下四個 8×8，每列 1 byte），1518 字。
  0–13 是視窗零件／半形字（每 32 bytes 含兩個 8×16 半形：半形 h 在 `0x88000 + 16h`，h = 2..11 是數字 0–9），14 = 全形空白。
  15– 是符號、全形數字與英文、平假名（沒有ゎゐゑ）、片假名、第一水準漢字（JIS 順序的子集），最後幾個是第二水準（傀儡凰卍帷眩芒麒）。
  字形 → 字元用系統日文字型依 JIS 順序做 DP 對齊、再逐字目視修正（`data/charset.txt`）。
- 敵人 179 的名稱 `90C4 …藤昌… 8EF7` 超出字型範圍，看起來是 Shift-JIS 的「斉」「樹」（斉藤昌樹，推定是開發用的假資料）；`rom.py` 輸出 `{90C4}` 形式。

### 職業

人物 +14 是職業碼，高 4 位元是類別（0x 忍者、1x 僧、2x 陰陽、3x 武）：
00 主人公；01 伊賀者 02 甲賀者 03 伊賀女 04 甲賀女 05 根来衆 06 風魔衆；10 僧侶 11 僧兵 12 山伏 13 羅漢；20 陰陽師 21 方士 22 飯綱使；
30 武士 31 浪人 32 剣術家。名稱在 root `0xB79A` 依此順序 17 個 0 結尾字串。

術：0–13 忍術（火・天・地三欄）、14–27 仙術（仙・法・神）、28–41 妖術；術畫面三欄各 5、4、5 個。

## sdata：初始狀態

開新遊戲時整塊（0xFE0 bytes）複製到 WRAM `$7E:EFF0`（sdata + k → `$EFF0 + k`）。到第一張地圖時只有 0–2、0x1A、0xBB4 與主角名不同。

| sdata + | WRAM | 內容 |
|---------|------|------|
| 0x30 | $F020 | 推定同伴 id（FF FF） |
| 0x38 | $F028 | 道具袋 45 bytes = 3 人 × 15 格物品號，FF = 空（主角開始有 20 00 32 = 忍者服 剣 三方手裏剣） |
| 0xBC | $F0AC | 主角名 12 bytes |
| 0xC8 | $F0B8 | 人物狀態 63 筆 × 32（人物 0–62） |
| 0x8A8 | $F898 | 103 bytes：同一國的下一個武將（從城主開始，FF 結束） |
| 0x90F | $F8FF | 1 byte + 16 × [大名][值 0–4]（值未解） |
| 0x930 | $F920 | 國 30 筆 × 18：[大名][城主][金 LE16][米 LE16][兵 LE16][+8][+9][+10–17 未解] |
| 之後 | | 三元組列表、多段 LE16 列表、"NULL"（未解） |

人物狀態 32 bytes：+0 人物號、+2 体力、+4 最大体力、+6 気力、+8 最大気力、+10 経験値（以上 LE16）、+12 レベル、+13 +14 未解、
+15 知力、+16 素早さ、+17 運、+18–21 術遮罩（全 FF = 該系統 14 個都會、各位元對應未解）、+22 力、
+23–27 推定裝備（頭、胴、武器、飛道具、護符；改了會影響攻撃力）、+28–30 未解、+31 旗標（bit 7 = 女）。
攻撃力、守備力、術防御力是算出來的。能力畫面的姓名、職業取自人物表（+0 人物號），其餘取自狀態記錄。
人物 63–104 沒有初始狀態記錄。

武將：每國的武將是「城主 → sdata + 0x8A8 的鏈」，103 人每人恰好在一國。

## 職業圖示（取代頭像）

SFC 版沒有人物頭像組（`0x104000–0x11C000` 是開場／結局場景圖）。能力畫面左上是 24×32 的職業圖示：
`0xD1500 + 0x180 n`（3×4 tile，4bpp，列優先），n = 0–15，上傳到 VRAM `0xB600`（BG1 tile 0x1B0–0x1BB），用 BG 調色盤 0。
職業 → 圖示：依職業順序 0 1 2 3 3 4 5 … 15（伊賀女、甲賀女共用 3）。調色盤依圖示是 `0x15E3C`（圖示 0 1 7 8 10 12 13 14）
或 `0x15E5C`（2 3 4 5 6 9 11 15）；這是 105 人在 Mesen 讀 CGRAM 的結果，選調色盤的 p-code 沒追到（找不到對應的表）。
`0x15C3C` 與 `0x15E3C` 內容相同，遊戲讀的是後者（`$02:DE3C`）。

## 地點地圖（城下町、町、村…）

`0x7A000`（`$0F:A000`）：LE16 位移表（相對表頭，第一個 = 0x60 → 48 張），每張 `[W][H][x][y]` + RLE。
x、y 推定是入口座標（16×16 格單位；多數 y = 2H − 1，即最下一列）。
RLE：byte b ≥ 0x80 → 一格 b & 0x7F；b < 0x80 → 後面一個 byte n，n 格 b。共 W × H 格。
遊戲（`$7E:72A3`，參數在堆疊：格數、來源、目的、bank）解到 WRAM `$7F:B000 + 4(W+8) + 4`，每列間隔 W + 8（四周 4 格邊框另外填）。
p-code 依地圖號讀 `$0F:A000 + 2m`（開新遊戲的村是地圖 34）。

一格 32×32 = 2×2 個 BG2 16×16 tile。町的 metatile 表在 jovl1 `0x326B0`（每格碼 4 bytes：左上、右上、左下、右下，108 個碼），
byte v → 圖塊 v（每列 8 個 16×16），圖塊 `0x99F00`（0x1C00 bytes）DMA 到 VRAM `0x4400`（tile 0x20），所以 tilemap 字 = `0x0800 | (0x20 + (v/8)·32 + (v%8)·2)`，
調色盤 2 = `0x15FDC`。`0x864AE` 有同一張表的另一份（0x1B0 bytes 相同），那份後面接著每格碼 2 bytes（`FF 01` …，推定通行屬性，未解）。

地圖 0–37 用這套圖塊畫出來都合理（城、護城河、街道、民家；15 是 8×8 空白），只有 34 由遊戲畫面確認；38–47（推定修験場／山）用它畫不出來，圖塊未解。
哪張地圖是哪個地點（地名 18 個、城下町 16？）未解。
