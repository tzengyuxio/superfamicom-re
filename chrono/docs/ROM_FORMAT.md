# クロノ・トリガー（SFC，日版）音樂格式

位址：CPU 位址寫成 `$bank:addr`，ROM 是 HiROM（`$C0:0000` = ROM 0x000000）；SPC 位址是 SPC700 RAM。驅動程式的位址取自傾印出的 SPC RAM。

## 1. 播放指令

- 65816 把指令寫進 `$1E00–$1E03`，再呼叫 `$C7:0004`：`$1E00` = 10 是播放，`$1E01` 是曲號（`$1E02`、`$1E03` 開機時是 FF）。標題畫面在第 98 幀要求曲號 30（log `$1E00` 寫入，emu）。
- `$C7:0004` 把那首的樂譜和用到的音色上傳到 SPC（埠 `$2140–$2143`），傳完 `$1E00` 清成 0；上傳會跨好幾幀。
- NMI 向量 `$00:FF10` 是 `JML $00:0500`（handler 在 RAM），所以 `tools/replay.py` 要傳 `nmi=0x000500`。

## 2. 曲目表

- `$C7:0D18`（ROM 0x070D18）：每首 3 bytes 的 CPU 位址，曲號 00–50 有效（00 只有 0x24 bytes，沒有音符），51 以後是 0。
- 每首開頭是長度 word，後面的資料原樣放到 SPC `$2000`（傾印出的 SPC 逐 byte 比對過，80 首都相同）。

## 3. 樂譜（SPC `$2000`）

和 FF6 同一代的 Akao 格式。

- 標頭：資料在 ROM 裡的 base 位址（bank 內 16 bit）、結尾位址、8 個聲軌指標、同樣 8 個再一次，然後是聲軌資料。資料裡的位址 a 對應 SPC `(a − base) & $FFFF + $2024`（曲 18 等的資料跨 bank，結尾位址比 base 小）。聲軌指標等於結尾位址的是沒用的聲軌。
- 00–C3：音符，op ÷ 14 是音高（12 延音、13 休止），op mod 14 查音長表 SPC `$1DB3`（C0 60 40 48 30 20 24 18 10 0C 08 06 04 03）。
- C4–FF：指令，參數長度表 SPC `$15CC`，處理程式表 `$1554`。和長度有關的：
  - F0 n：tempo（`$1722`：存 n + n × 20 ÷ 256 到 `$47`）
  - E2 n：迴圈開始，共 n + 1 次；E3：迴圈結束
  - F5 n addr：迴圈第 n 次時跳出到 addr
  - F6 addr：跳躍（樂譜的循環就是聲軌 0 結尾的 F6）
  - EB–EF、FE、FF：聲軌結束（`$1D4A`）
- 計時：計時器 0 每 `$2A` × 125 µs = 5.25 ms 一步；每步把 tempo 加進 `$48`，進位時走一 tick（`$037A`）。
- 主迴圈在 `$029C` 用 `MOV Y,$FD ; BEQ` 等計時器 0 的計數非 0，不管累積了幾步都只處理一步。所以驅動處理不及時會漏步，實際播放比樂譜慢；慢多少看曲子，量到的是 0–1%。

## 4. 傾印與輸出（`tools/music.py`）

- 開機到第 60 幀存 savestate；每輪在 Lua 裡攔 `$1E00` = 10 的寫入，把 `$1E01` 換成目標曲號（信箱 `$7F:FFFF`）。
- 等 SPC 第一次寫 DSP KON（`$4C`，由 SPC `$02BA` 的 `MOV $F3,A`）時傾印 SPC700 狀態，再把 PC 倒回 `$02BA`。SPC 檔從第一個音開始，前奏秒也從第一個音算。在幀結束時傾印的話，大曲子會停在上傳中途（無聲）；在 KON 前一幀傾印，有的曲子同樣還在上傳。
- 循環長度：先從樂譜算，再用 libgme 播放，比較前奏後 8 秒的 10 ms 能量包絡和一個循環後的包絡，在樂譜長度的 −0.5% 到 +3% 之間找相關最高的位置。相關 ≥ 0.9 才採用，前奏按同一比例放大；比不出的維持樂譜值。長度只決定淡出從哪裡開始，曲子本身是驅動連續播放，循環接縫不受影響。
- 外部對照 `data/music_zophar.tsv`（reference：Zophar's Domain「Chrono Trigger」SPC 合集 EMU 版，<https://www.zophar.net/music/nintendo-snes-spc/chrono-trigger>，2026-11-07 取得，美版）：
  - 比對方式：Zophar SPC 的 RAM `$2024` 起和 ROM 的樂譜比。完全相同的寫「byte 相同」；美版的資料位址不同，跳躍指令的位址也跟著不同，所以多數只有「開頭 32 bytes 相同」；05、48 是相似度比對（0.93、0.99）。
  - 71 個曲號對到 Zophar 92 個檔裡的 79 個。沒對到的曲號是 12、19、1A、20、21、34、37、41、43，多半是 2–8 秒循環的環境音。Zophar 沒對到的是 Battle 2、Singing Mountain、Blackbird 等 13 檔：可能是日、美版樂譜差較多，或是用音效通道播的。
  - 48 在 Zophar 叫 Magus' Castle，但樂譜只有 0x171 bytes、26 秒就結束（Zophar 的檔也是 26 秒）；40 同時對到 Confusing Melody 與 Ozzie Scream。
- 未解：各曲在遊戲中的場景；E2 迴圈次數 n + 1 是從 FF6 的格式推的，沒有讀處理程式確認；E8 等其他指令（不影響長度的假設也沒驗證）；樂譜比對不出的 35 首的實際長度。
