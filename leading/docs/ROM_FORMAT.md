# SFC リーディングカンパニー ROM 格式

位址寫法：`$BB:AAAA` 是 CPU 位址（LoROM），「ROM 0x……」是去掉 header 後的檔案偏移，`lorom(bank, addr) = (bank & 0x7F) × 0x8000 + (addr & 0x7FFF)`。WRAM 位址 `$xxxx` 都在 `$7E`。

## 1. 硬體與引擎

- 1 MB LoROM，無 header。程式是 C 編譯出來的原生 65816 程式，引擎和エアーマネージメントII 相同。ROM 裡留有組語原始碼字串殘片（如 `lda 28, s`）。
- 服務分派器 `$00:8000`（實體在 `$00:8D2A`）：呼叫端把服務號與參數壓在堆疊，分派器把它們複製到 direct page `$52..`（服務號在 `$52`），經服務表 `$00:97B3` 跳去。常用服務：

  | 服務 | 入口 | 用途 |
  |------|------|------|
  | 17 | `$00:9BA6` | memcpy：`[$40]` → `[$44]`，長度 `$4E` |
  | 24 | | memset |
  | 3C／43／4F／61 | `$00:AE9B`／`$00:B64D`／`$00:B659`／`$00:B668` | printf 類，進入時 va 指標在 DP `$54` |
  | 55 | `$00:B62F` | sprintf，va 指標在 DP `$58` |

  va 指向 `fmt`（24-bit）後接參數 words。驗證腳本 hook 這 5 個入口記錄遊戲印出的字（`tools/lc.py` 的 `PRT_LUA`）。**不要 hook `$00:8000` 本身**：本作服務 0F 每幀被叫上千次，一輪重播從約 15 秒變成 110 秒。
- `$01:D020`：`base + idx × size`（陣列定址）。
- 文字是 ASCII 小寫與 Shift-JIS；字型把 a–z 畫成大寫，所以名稱表存的是 `jvd`、`vector`，畫面上是 `JVD`、`VECTOR`。

## 2. 檔案表（ROM `0x6000`）

16 bytes 一筆：名稱 8 bytes、bank LE16、位址 LE16、大小 LE32；名稱第一 byte = 0 結束。共 254 個檔（`output/files.csv`）。有同名重複（`GAME`、`S1_JVD` 等），遊戲用 `$00:98DE` 依名稱從頭掃，取第一個。多數圖形檔是 KOEI LZ（共用 `tools/koei_lz.py`，壓縮表在 ROM 0x2AE6）；`LK*`／`LD*`／`LC` 是 SPC 音樂。

本專案用到的檔：

| 檔 | 內容 |
|----|------|
| `PRESIDEN`／`COMPTOP`／`SECRETAR`／`MANLABO`／`MANFACTO`／`MANBUSID`／`MANACCOU` | 頭像 4／12／12／4／4／4／4 張（§6） |
| `KAO` | 頭像調色盤 16 色（全員共用） |
| `OFFCBACK`（LZ，6016 bytes） | 主畫面街區（BG2）：調色盤 32 bytes、tilemap 32 × 18 words、151 個 4bpp tile |
| `BUSI_L1-5`／`FACT_L1-5`／`LABO_L1-5`（LZ，各 5760 bytes） | 營業所／工場／研究所 5 級，每級 5 個變體 × 1152 bytes（6 × 6 tiles） |
| `EQUIP` | 前 32 bytes = 建物調色盤（BG 調色盤 3） |

| `$0C:E02C` | 8 × LE16：等級的定價（千円）400 320 260 200 150 100 70 40 |
| `$0C:E03C` | 8 個指標：等級名 `basic1 basic2 standard1 standard2 standard3 super1 super2 pro` |
| `$0C:E092` | 8 個指標：定價文字 |
| `$0C:E0C8` | 機能 9 × 25 bytes：bit LE16、名稱 SJIS[16]、b18、w19、w21、w23（未解）。チューナー、タイマ予約、リモコン、長時間録画、バーコード、ＢＳチューナ、編集機能、Ｗカセット、ハイビジョン |

## 4. 劇本與開局狀態（bank `$02`）

劇本號在 WRAM `$46DE`（0／1）。選劇本按 YES 後約第 5550 幀，`$02:BF2B`–`$02:C4E3` 建開局狀態；每個表是「base + 劇本 × size」：

| ROM 表 | 每劇本大小 | 去處 |
|--------|-----------|------|
| `$02:DDC3` | 0x2D（9 × 5） | 機能記錄 `$5627 + 0x1D × i` 的 +0x18（+0..0x17 是 `$0C:E0C8` 記錄的前 24 bytes） |
| `$02:DE1D` | 0x5E8 | 產品 `$4E19` 原樣（4 協議會 × 6 槽 × 63 bytes，§5） |
| `$02:DB83` | 0x48（4 × 18） | 協議會記錄 `$4C59 + 0x70 × i`：+0 ← id LE16（FFFF = 不存在；劇本 2 的 VCD 不存在），+0x40 ← 4 × LE32 開局前四季的市場規模（百萬円，第 4 季 0，由遊戲模擬補上）；名稱在 +4 |
| `$02:DC13` | 0xD8（12 × 18） | 廠商記錄 `$4785 + 0x67 × i`：+0x0C ← rom 0..11（format、leader、信用度 × 4 協議會、產品槽…），+0x18 = 該廠商產品的 24-bit 指標或 0，+0x1D ← rom 14..17（LE16 如 3800，未解；LE16 0）；名稱在 +2 |
| `$02:E9ED` | 0x140 | `$5401` 原樣（未解） |
| `$02:EC6D` | 0xA8 | `$5541`，之後存在的協議會 4 × 14 bytes 重算（未解） |
| `$02:EDBD` | 0x844 | `$6E05` 原樣（未解） |

市場格 `$5785`：8 × 8 格 × 0x5A bytes（子程序 `$02:C4E4`）；列 = 等級、欄 = 產品 +0x0F；+0 是格內產品數，+2 + 21 × f 是協議會 f 在此格最後一個產品的指標，+0x56 LE32 = 3000。`$572C`、`$7668` 另有 memset／設值，沒有列入比對。

廠商記錄的 4 個信用度：畫面顯示值和 ROM 值差 1（推測顯示時另有加減）。劇本 1：VECTOR／PONY／NATIONAC／TOSHIMA 是 4 協議會的 leader。

## 5. 產品記錄（63 bytes，`$4E19 + f × 0x17A + p × 0x3F`）

| 偏移 | 內容 | 依據 |
|------|------|------|
| +0 | 槽號 | |
| +2 | 狀態 LE16：2 発売中、0 開発中、FFFF 空 | |
| +4 | 名稱 9 bytes | |
| +0x0E | 等級 0–7（也是市場格的列） | 產品畫面印等級名 8/8 |
| +0x0F | 市場格的欄（意義未解） | |
| +0x10 | 製造廠商 0–11 | 產品畫面印廠商名 12/12；營業員、製造員、合理化、費用、利益跟著變 |
| +0x11 | 契約：0 original（自社）、1 license、2 OEM | 產品畫面印 `original`／`license`／`oem` 3/3 |
| +0x12 | LE16：自社 100、license 5／10、OEM 60／65（推測為權利金或分成比例；畫面不印） | |
| +0x21 | LE16 新鮮度 | 改值後畫面數值相同 |
| +0x23 | LE16（改值會改材料費，未解） | |
| +0x25 | LE16 稼働率 | 改值後畫面數值相同 |
| +0x27 | LE16 認知度 | 改值後畫面數值相同；開局值 = ROM |
| +0x29 | LE16（ROM 40，未解） | |
| +0x2F | LE32（改值會改費用與利益，推測本季產量或銷量） | |
| +0x33、+0x37 | LE32（推測過去季的數值） | |

新鮮度、稼働率在第一回合主畫面時已被遊戲更新（ROM 42 → 畫面 39、0 → 3）。產品畫面的定價（`\%d,000`）不跟 +0x0E 變，存在別處（未解）。

## 6. 頭像

- 種類表 `$01:C491`：7 個指標指向檔名 `PRESIDEN`（会長 4）、`COMPTOP`（社長 12）、`SECRETAR`（秘書 12）、`MANLABO`／`MANFACTO`／`MANBUSID`／`MANACCOU`（開發／生產／營業／經理部長各 4），共 44 張。
- 每張 2400 bytes：40 × 48 的 5 × 6 個 4bpp tile（列優先，960 bytes），後接 3 條 5 × 3 tiles（480 bytes）的動畫條，蓋在 tile 列 1–3（說話／眨眼）。動畫條的位置是比對推得，只看到 strip 0 出現，沒有獨立驗證。
- 調色盤只有一組：`KAO` 檔 16 色。
- 繪製 `$01:A58F`：堆疊 +8 = 種類、+10 = 圖號；`KAO` → CGRAM 0x1E0（精靈調色盤 7），臉 → VRAM byte 0xBC00。畫面上的動畫另由 NMI 把臉放到 VRAM 0x53C0（狀態由呼叫端設，不跟引數），所以驗證時要讀 0xBC00。
- 協議會選擇畫面的社長頭像：COMPTOP 圖號 = 協議會序號（`$02:9E3F` 迴圈），看不出與 leader 廠商的對應，kaodata 不給名字。

## 7. 主畫面街區地圖

BG mode 1。

- BG2 = `OFFCBACK`：調色盤 → CGRAM 0x40（調色盤 2），tilemap 32 × 18 → VRAM byte 0xF000，151 tiles → VRAM byte 0x6000。
- BG1 = 4 個建物格：tile 欄 3／10／17／24、列 2–7，每格 6 × 6 tiles，用 BG1 tile 0x3E + 36 n、調色盤 3（`EQUIP` 前 32 bytes），BG1 tilemap 在 VRAM byte 0xE800。每格是 `BUSI`／`FACT`／`LABO_L1-5` 其中一個變體。
- 劇本 1 開局的 4 格 = `LABO_L2#2`、`LABO_L2#2`、`FACT_L1#1`、`BUSI_L2#1`；設施等級／變體的選擇規則未解。
- 畫面下方的 8 × 8 菱形市場格是靜態圖。

## 8. 操作序列（驗證用，幀數從開機算）

`tools/lc.py`：標題約 4200 幀接受 START → NEW GAME → 劇本選單（約 4870）→ 劇本（劇本 2 先按下）+ 說明 + YES，約 5550 建開局狀態 → 玩家 1 人 → 協議會 JVD + YES → beginner → 名稱不改（右 + A）→ 確認；之後 4 次 A 到会長講話（約 9335 畫会長頭像），再 10 次到主畫面（約 11450）。主畫面 → 右 → A ×3 → B ×3 → 右 → A ×2 是 JVD 第 0 槽產品（劇本 1 為 HITASHI 的 `hit 1bas`）的產品畫面（約 13490，`SHEET_STEPS`）。

## 9. 未解

- `$5401`、`$5541`、`$6E05` 的內容（數值已和 ROM 逐 byte 對上，只是不知道意義）；`$572C`、`$7668`。
- 廠商記錄 rom +14（LE16，如 3800）、+16；信用度畫面差 1 的原因。
- 產品記錄多數欄位（+0x0F、+0x12、+0x13–0x20、+0x23、+0x29、+0x2B–0x3E）；產品定價存放處。
- 機能記錄的 b18、w19、w21、w23（疑為登場時期、開發費用等）與劇本 5 bytes 的意義。
- `$0C:E022` 5 個值（50–800）；販促費用；研究、生產、營業的參數表。
- 建物等級與變體的選擇規則；市場格欄的意義。
- 頭像動畫條（strip 1、2）的位置沒有獨立驗證。
- 事件、結局、COM 廠商的行為；多數檔的用途。
- 本作沒有戰鬥，沒有戰術地圖。
