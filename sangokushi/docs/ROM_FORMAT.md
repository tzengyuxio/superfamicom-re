# SFC スーパー三國志 ROM 格式

KOEI，SFC。檔案 `roms/Super Sangokushi (Japan).zip`（1 MB，只有一個版本，SHA-1 `6040fe870205c6221ebe4d3023451e3e701620ff`）。FC 版 `三國志`（`~/works/famicom-re/sangokushi/`）的移植：人物 255、國 58、州 15、劇本 5、勢力 14 都和 FC 一樣。

本文的偏移一律是**檔案偏移**（無 copier header 的映像）。CPU 位址寫成 `$bb:aaaa`，HiROM：檔案偏移 = `位址 & 0x3FFFFF`（`$C0:0000` = 檔案 0）。WRAM 位址寫成 `$7E:xxxx`（或只寫 `$xxxx`）。「推測」表示沒有獨立驗證過；「未解」表示意義不明，匯出時只輸出原始值。

## 1. 硬體與引擎

| 項目 | 內容 |
|------|------|
| 標頭（`0xFFC0`） | `SUPER SANGOKUSHI`，map mode `31`（HiROM），ROM 1 MB，SRAM 8 KB |
| 向量 | native NMI `$00:8F92`（`tools/replay.py` 自動掛在 `$00:8F93`），reset `$00:800F` |
| 程式 | C 編譯出來的碼：引數放堆疊、`JSL` 呼叫。乘法 `$C1:DCAA`、加法／指標運算 `$C1:DA49` 等小常式；`$00:1772` 是 MVN 區塊複製（開新遊戲的劇本複製就是它） |
| printf | `$C2:16DC`：格式字串的 24-bit 指標在 `sp+4`，引數區的 16-bit（bank 0）指標在 `sp+8`；`%d` 取 2 bytes、`%ld` 4 bytes、`%s` 4 bytes（24-bit 指標）。所有驗證都靠攔它（`tools/printf.py`） |
| LZ 解壓 | `$C0:F194`（`tools/koei_lz.py`，表在 `0xF037`） |

### 操作序列（`tools/sequences.py`，按鍵按住 10 幀，之後一律放 20 幀，和 `tools/replay.py` 相同）

| 名稱 | 內容 | 結束幀 |

## 2. 壓縮資料

| entry | 內容 |
|-------|------|
| 187–244 | 58 國戰場的 BG2 tilemap（§9） |
| 245–302 | 58 國戰場的格子（§9） |
| 303–430 | 肖像 128 張（§7） |
| 431 | 戰場的 BG 字元（§9） |

## 3. 字型與文字

- **字型**：`0x87BF3`（`$C8:7BF3`），921 字，每字 16 × 16 1bpp、32 bytes（4 個 8 × 8：左上、右上、左下、右下，每列 1 byte）。遊戲畫字時把每個 byte 寫成 2bpp 的兩個 plane（顏色 3），一個字是連續 4 個 2bpp tile。
- **兩 byte 字碼**：big-endian `0x8140 + g` = 字 g。低 byte 是 `00` 的碼寫成跳脫碼 `0x9140 + k`（= `0x8200 + 0x100 k`），只有字 192、448、704 三個。
- **單 byte**：`0xA1–0xDF` 是 JIS X 0201 半形片假名（名表讀音、劇本名的「ﾉ」等）；`0x20–0x7E` ASCII（空白、printf 格式）；`0x1B` 是顯示用的跳脫碼（`1B 43 n` 換顏色 n，其他 `1B x` 兩 byte），解碼時丟掉。
- **字表** `data/charset.txt`（32 字一行）：0 々、1 …、2「100」合字（寫成〓）、3 Ｌ、4 Ｒ；5–828 JIS 第一水準漢字子集（JIS 順序）；829–888 第二水準（JIS 順序）；889–920 額外的人名用字（不照 JIS 順序）。字形 → 字元是人工判讀，遊戲無法驗證；以 255 個人名和 FC 版逐一比對修正（例：字 842 是「旻」，董旻）。
- 人名用了兩個近似字：郭汜寫成「氾」（字 641）、梁剛寫成「粱」（字 862）。ROM 解碼照字形輸出；kaodata 匯出時改回 FC 資料集的寫法（`export_kaodata.py` 的 `NAME_FIXES`）。

## 4. 名表（`0x5C314`，256 筆 × 18 bytes）

| 偏移 | 內容 |
|------|------|
| +0–7 | 讀音（半形片假名，0 補滿；姓與名之間沒有分隔） |
| +8–13 | 漢字 3 個（BE16 字碼，0 = 無）。printf 以 `%s` 指向 +8 畫姓名 |
| +14 | 0（全部） |
| +15 | 頭像碼（§7） |
| +16–17 | 生年（BE16）；年齡 = 劇本年 − 生年 |

名表的 index 就是人物編號 p。p = 0 是另一筆「曹操」（頭像碼 3、能力 88 90 91 97 90，比 p1 低），遊戲的武將一覽不列出它（用途未解）；國的太守欄是 0 時畫面顯示 p0 的名字（即「曹操」），所以太守 0 = 無。

和 FC 版的差異：74 楽就（FC 梁紀）、197 韓浩（FC 陳嬉）、204 劉賢（FC 劉延）、239 向寵（FC 尚寵）是換人或改名；讀音不同的有 47 孫乾（ｿﾝｹﾝ）、94 蔡邕（ｻｲﾖｳ）、127 李堪（ﾘｶﾝ）、143 張邈（ﾁｮｳﾊﾞｸ）、194 張顗（ﾁｮｳｶﾞｲ）、242 夏侯楙（ｶｺｳﾎﾞｳ）；字形上 66 袁熙、70 張勳、158 陳羣 是 FC 資料集寫法（煕、勲、群）的異體。

| 項目 | 內容 |
|------|------|
| BG1 字元 | LZ `0x2C00` → VRAM `0xA020`（字元基底 `0xA000`；tilemap 的 tile n ≥ 1 = 串流的第 n − 1 個 tile） |
| BG1 tilemap | `0xC426`，30 × 22 個 word（tile、調色盤 2），遊戲以 DMA 一列 `0x3C` bytes 寫到 VRAM `0x9800` 的第 1–22 列、第 1–30 欄。ROM 其實有 23 列，第 23 列（調色盤 3）在訊息窗下面，不算地圖 |

| BG2（支配勢力上色層） | LZ `0x74D7` → VRAM `0x4020`（30 × 22 個 tile 的遮罩：1 = 陸地內、0 = 邊界與海）；BG2 tilemap 在 VRAM `0x3800`，第 (y + 1) 列 (x + 1) 欄 = tile `1 + 30 y + x`、調色盤 3 |

| 國標籤 | 他国畫面的國號是 sprite（c 國 = tile `0x63 + c`），位置的來源未解 |

## 7. 頭像

頭像 40 × 48 = 5 × 6 個 4bpp tile（960 bytes，row-major），由 `$C1:143F(code)` 載入到 VRAM `0xEC80`，畫成 30 個 8 × 8 sprite（tile `0x164–0x181`，OBJ 調色盤 1）。調色盤 `0x4E711`（CGRAM `0x120`），全部頭像共用。

| 頭像碼 | 種類 | 內容 |
|--------|------|------|
| `0x00–0x7F` | 肖像 128 | LZ entry `303 + code` |
| `0x80–0xFE` | 男性組合 127 | 6 型；紀錄 `0xAEA6 + 6 (code − 0x80)` |
| `0xFF–0x132` | 女性組合 52 | 2 型；紀錄 `0xB1A0 + 6 (code − 0xFF)` |

組合紀錄 6 bytes：部位 0–4 的變體、型 t。部位 k 變體 v 的圖 = 指標表 `parts + 75 t + 3 (first[k] + v)` 指向的 LZ 串流，從位置表 `pos + 20 t + 4 k`（x、y LE16，單位 tile）那格開始連續寫入（依部位順序覆蓋）。

| 種類 | parts | first（LE16 × 5） | pos | 各部位變體數 |
|------|-------|------------------|-----|------|
| 男性 | `0xEDE29` | `0xEE23F` | `0xEE1BD` | 5、5、7、2、6 |
| 女性 | `0xEDFEB` | `0xEE235` | `0xEE195` | 6、6、6、2、5 |

部位 0 = 第 0–3 列（或 0–2 列）、部位 1 = 其下各列、部位 2–4 是第 2–4 列的 2–3 個 tile（推測：眼、鼻、口）。

255 個人物：頭像碼 0–127 與 128–254 各用一次（肖像 128 人、男性組合 127 人）。女性組合沒有人物使用（推測：君主的姫；FC 版的姫頭像由勢力編號與 W 算出，SFC 未驗證）。

## 9. 戰場

| 項目 | 內容 |
|------|------|
| 選圖 | WRAM `$2720`（word）= 被攻打的國的紀錄位址（`$2052 + 30 (c − 1)`）；c 國用 entry `187 + c − 1`（tilemap）與 `245 + c − 1`（格子） |
| 格子 | 14 欄 × 12 列，每格 1 byte：`地形 << 3 | 布陣區`，奇數欄比偶數欄低半格；解壓後放 WRAM `$9499` |
| tilemap | 28 × 25 個 word（BG2），一格 = 2 × 2 tile（欄 x、列 y 的格在 tile (2x, 2y + (x & 1))）；解壓到 WRAM `$7F:8000`，畫面在 VRAM `0x3800` 的 (2, 2) 起 |
| 字元 | entry 431 → VRAM `0x4C00`（tile `0x60` 起，字元基底 `0x4000`） |
| 調色盤 | 5 = `0x4E771`、6 = `0x4E791`、7 = `0x4E7B1 + 32 k`（k = 0–2 循環，顏色 7–15 動畫） |
| 城 | ROM 的格子裡沒有城（地形 4）。城位置表 `0x2EED2`：58 國 × 10 bytes，每個位置 `(欄 + 1) << 4 | (列 + 1)`，`FF` = 無。戰爭開始時 `$C3:836F` 把前 n 個位置（n = 國 +18 的城數）的格子 OR 上地形 4，並畫 2 × 2 的城 tile `0x15A4–0x15A7`。後面多出來的位置推測是築城用的 |

地形（看圖命名，沿用 FC 筆記）：0 平地、1 山、2 森林、3 河、4 城、5 雪山。

和 FC 版（`0x259B4`）比：FC 的格子直接含城格（233 格），SFC 把城移到城位置表，劇本 1 的城數與前 n 個位置正好重現 FC 的 233 個城格；其餘差異是布陣區值（2↔3 共 33 格、10↔11 共 27 格、8→10 1 格）。

## 10. 未解

- 國：+0–1、+13、+16、+17、+18 高 4 位、+19、+20–29；靜態國表 +1 旗標、x、y；開局處理改動的欄位與 9 國支配勢力變成 0 的原因；「在野」的計算
- 人物 +7 bit 1、+15–17
- 勢力 +2、+7–20（推測友好度）、+21–76
