# SFC 横山光輝 三国志 ROM 格式

エンジェル（バンダイ），1992，SFC。檔案 `roms/Yokoyama Mitsuteru Sangokushi (Japan).zip`（Rev 0）與 `roms/Yokoyama Mitsuteru Sangokushi (Japan) (Rev 1).zip`（Rev 1），都是 1 MB LoROM。不是光榮的作品：沒有 KOEI LZ、沒有 Shift-JIS，資料格式全部自成一套；只有「國＋武將＋勢力、每月政略／軍略／行軍三階段」的遊戲結構像光榮的三國志。

本文的位址一律寫成 CPU 位址 `$bb:aaaa`，LoROM：檔案偏移 = `(bb & 0x7F) × 0x8000 + (aaaa − 0x8000)`（`rom.off()`）。WRAM 寫成 `$xxxx`（bank `$7E`）或 `$7E:xxxx`。「推測」表示沒有獨立驗證過；「未解」表示意義不明，匯出時只輸出原始值。

| 版本 | SHA-1（.sfc） | 版本 byte `$00:FFDB` |
|------|---------------|-----------------------|
| Rev 0 | `1ac159270b5b9026081abf45290c6c83f734d235` | 0 |
| Rev 1 | `c535fe761e106607d518edb06fe5ff468ac8c4de` | 1 |

## 1. 硬體與引擎

| 項目 | 內容 |
|------|------|
| 標頭（`$00:FFC0`） | `SFX ﾖｺﾔﾏﾐﾂﾃﾙ ｻﾝｺﾞｸｼ`，map mode `20`（LoROM），ROM 1 MB，SRAM 8 KB |
| 向量 | native NMI `$00:80B5`（第一條是 `REP #$30`，`tools/replay.py` 自動掛在 `$00:80B7`），reset `$00:8000` |
| 程式 | 手寫組合語言（不是 C）：JSR／JSL、直接頁 `$00–$FF` 當暫存 |
| 文字輸出 | `$00:8D60`：A = 一個字碼（§3），畫進 WRAM 的文字緩衝（`$2180`）。所有文字驗證都攔它 |
| LZSS 解壓 | `$01:F8FE`（Rev 1 `$01:F903`）：A = 來源位址、X = bank，輸出到 `$7E:8000`（§2） |
| OAM／CGRAM 影子 | OAM `$7E:2000`（544 bytes，每幀 DMA），CGRAM `$0500`（512 bytes） |

### 操作序列（`tools/sequences.py`，按鍵按住 10 幀，之後放 20 幀，和 `tools/replay.py` 相同）

| 名稱 | 內容 |
|------|------|
| `TO_SCENARIOS` | 標題 → START → a（ゲームスタート）→ a（新しく始める）→ 劇本選擇（189 年／219 年） |
| `scenario(k, d, r)` | 劇本 k（下 = 219 年）→ 難易度 1 2 3（左右）→ 君主（189 年 2 列 × 3：袁紹 曹操 孫堅／董卓 劉備 馬騰；219 年 曹操 孫権 劉備）。劇本載入程式在選完君主後執行 |
| `TO_MAP[k]` | → 開場文字、開局事件 → 第一個月的大地圖（玩家的政略フェイズ；189 年袁紹、219 年曹操）。電腦勢力在玩家之前已經行動 |
| `TO_PICK_COUNTRY[k]` | 地圖上 a（國的資訊列）→ a（指令選單 開発 統治 租税 防災 情報／輸送 人事 同盟 政策）→ 右 × 4（情報）→ a → 右（武将）→ a：「どの国の武将をご覧になりますか？」 |
| `TO_PICK_INFO[k]` | 同上但選「国」：「どの国の情報をご覧になりますか？」 |
| `DETAIL_STEPS` | → a、a（國的資訊列、武將列表「どの武将の情報を」）→ a（第一位的概要）→ a（武將詳細畫面：姓名、所屬、讀音、全部欄位、頭像） |

地圖上 a 只在游標停在國上時有反應：開機序列在到地圖後 5 幀把游標 `$0113`／`$0115` 寫成玩家的國（`sequences.cursor_lua`），每輪再用 WRAM patch 寫成要查的國（`cursor_patch`）。游標用方向鍵移動不可靠（有加速），所以一律直接寫。

## 2. LZSS 壓縮（`$01:F8FE`，`rom.lz`）

開頭 LE16 = 輸出大小，接著是旗標 byte（LSB 先），每個旗標：1 = 一個字面 byte；0 = 一個 LE16 字 w，從 `w >> 4` bytes 之前複製 `(w & 15) + 3` bytes（指到開頭之前的位置讀成 0）。`$01:F9A1` 是包裝：解壓後再把開頭 8 bytes 等拿去設定 DMA。開機到第一個月的地圖之間遊戲解壓 20 個串流（`$06:F135`、`$0F:C47C`、`$10:83CC`–`$10:F1EB`、`$16:8000`、`$16:8F73` 等，標題與選單圖），內容沒有一一辨認。頭像與大地圖都**不是**壓縮資料。

## 3. 字型與文字

- **字碼**：16-bit LE，`0x0000` 結束，`0x000A` 換行。
  - `0x200–0x5FF`：16 × 16 字，`$03:8000 + 32 × (code − 0x200)`（1bpp，4 個 8 × 8：左上、左下、右上、右下，每列 1 byte）。`$00:8DC0 LDA $03:8000,X`。
  - `0x100–0x1FF`：8 × 16 半形字，`$04:8800 + 16 × (code − 0x100)`（`$00:8DEF`）。
  - `< 0xF1`：當作 `code + 0x10`（落在半形區；文字裡沒看到用）。
  - `0xF1–0xF9` 控制碼（`$00:8E67`）：F1 武將名（`$1DCC + 5 × $0448`，玩家勢力的君主）、F2 君主名（`$1B41 + 0x15 × $6F`）、F3 武將 `$75`、F4 武將 `$87`、F8 武將 `$89`、F5 3 位數 `$65`、F7 4 位數 `$65`、F9 4 位數 `$67`、F6 國名 `$6D`。
  - `0x600–0x63F` 會讀到 `$04:0000` 以後（LoROM 那裡不是 ROM），不是文字。
- **字表** `data/charset.txt`（16 字一行）：0x100–0x1FF 半形（數字、英文、片假名、平假名、符號）；0x200–0x5FF 全形（數字、英文、假名、地名、人名用漢字、一般漢字）。字形 → 字元是人工判讀（`tools/charset_sheet.py` 畫字形與字元對照）；名表照讀音的五十音排序，可以拿來交叉檢查。325 候 與 352 侯 是不同字形（夏候淵、夏候惇用 325）。0x1FA–0x1FF 是半形合字、0x225／0x226 是圈字（政、軍）、0x236–0x23A 是圖示，寫成 □。
- **Rev 1** 改畫了 0x342：緒 → 褚（許緒 → 許褚；`rom.REV1_CHARS`）。
- 訊息字串在 bank `$1F`（例：`$1F:CE06`「どの武将の情報を⏎ご覧になりますか？」），沒有整理成表。

## 4. 名表（`$04:B080`，224 筆 × 8 bytes）

| 偏移 | 內容 |
|------|------|
| +0–1 | 姓（字碼） |
| +2–3 | 第二字（`0x200` = 無；複姓與三字名用，例：諸葛亮 = 諸 葛 亮、司馬懿） |
| +4–5 | 名 |
| +6–7 | 讀音字串的指標（`$04:xxxx`，半形片假名字碼，0 結束） |

index 就是人物編號 p（0–223），照讀音的五十音排序（伊籍 0 … 劉備 211 …）。Rev 1 的讀音改了一筆：135 張嶷 チョウギ → チョウギョク。

## 5. 開新遊戲：劇本資料（`$01:D4A9`，`rom.Rom.scenario_wram`）

`$011F` = 劇本（0 = 189 年、1 = 219 年）。載入程式用 `LDX #表0 ; LDA $011F ; BEQ ; LDX #表1` 選表（`Rom._find` 用這個樣式找位址，Rev 1 有幾個表往後移 4 bytes）：

| 表 | 189 年 | 219 年 | Rev 1 | 大小 |
|----|--------|--------|-------|------|
| 開始年 | 0xBD | 0xDB | | |
| 人物 | `$04:9800` | `$04:A440` | 同 | 224 × 14 |
| 配置 | `$04:C072` | `$04:C4D2` | +4 | 224 × 5 |
| 國 | `$04:EF48` | `$04:F138` | +4 | 31 × 16 |
| 勢力君主 | `$04:F594` | `$04:F5A3` | +4 | 15 × 1 |

1. 人物 14 bytes → `$7F:8000`，再搬進 WRAM 人物紀錄 `$0800 + 22 p` 的 +4–17；配置 → `$7F:8C40`。
2. 國 16 bytes → WRAM 國紀錄 `$1B40 + 21 c` 的 +1–16（+0 與 +17–20 = 0），31 國。
3. 人物紀錄 +0–3 依配置：種類 0（仕官）→ +1 = 國 \| 0x80、+0 = 該國勢力 \| 0x80；種類 FF（不在）→ +0 = 0xC0；其他 0。+3 = 経験値 / 100 + 1（レベル）。
4. 勢力紀錄 `$1DCB + 5 f`（15 個）：[君主 = FF 時 FF，否則 0][君主][FF][0][0]。
5. 難易度 `$044A` = 0（畫面上的「1」）：每國 金、米 × 160 / 100（`$01:C413`）。
6. 難易度 2（「3」）（Rev 0 `$01:D612`，`Rom.loader_done`）：玩家以外的君主 経験値 +999（`$01:C8C1`，升級常式 `$01:C8FF` 會改能力），再對 `$0810 + 5 f`（16-bit）`ORA #$3F`——index 用勢力 × 5 卻寫進人物區，看起來是 bug；這一步沒有解析。

### 配置（5 bytes：種類、國、參照、年、?）

| 種類 | 意義 | 例 |
|------|------|----|
| 0 | 仕官：開局在「國」為該國勢力效力 | （已驗證：載入程式依此填 +0／+1） |
| 1 | 在野：「年」起出現在「國」（推測） | 尹楷 01 02 FF C5：197 年冀州 |
| 2 | 親族：「參照」人物的親族，「年」起登場（推測） | |
| 3 | 「年」起在「國」加入勢力「參照」（推測） | 周瑜 03 08 06 C2：194 年南昌、孫堅軍；荀彧 → 曹操軍 |
| 4 | 推挙：由人物「參照」推薦（推測） | 周倉 → 36 関羽；219 年 祝融等 → 192 孟獲 |

| 偏移 | 欄位 |

| +0 | 勢力（FF = 無） |
| +1 | 太守（人物編號） |
| +2–3 | 金 |
| +4–5 | 米 |
| +6–7 | 民（× 1000 顯示） |
| +8–9 | 収穫高 |
| +10–11 | 産業値 |
| +12 | 統治度 |
| +13 | 防災値 |
| +14 | 税率 |
| +15 | 城塞値（地圖的城框樣式：< 0x21、< 0x42、其他） |

國名 `$04:F328`（Rev 1 `F32C`，31 × 2 字碼，`$00:8EB8`），讀音指標表緊接在後（31 × 2 bytes → `$04:xxxx` 字串）。位置 `$04:F532`（Rev 1 `F536`，31 × (x, y)，單位是縮小地圖的 4 px = 地形格），`$01:CAB5` 用游標 `$0113 >> 4`、`$0115 >> 4` 在 ±2 格內找國。沒有找到相鄰表：行軍是在 64 × 64 地形格上移動（§8）。

## 6. 勢力

勢力 f 只有君主一個欄位（§5 表）。189 年 14 個（袁紹 袁術 王朗 孔融 公孫瓚 曹操 孫堅 陶謙 董卓 張魯 馬騰 劉表 劉焉 劉備；f = 11 空）、219 年 3 個（曹操 5、孫権 6、劉備 14）。可選君主（189 年 袁紹 曹操 孫堅 董卓 劉備 馬騰）是畫面上看到的，ROM 的選單表沒有解析。玩家勢力在 `$0448`。

## 7. 頭像（sprite 組合，48 × 64）

`$00:8B4D` 用人物編號 `$0139`：

1. 從 `$04:C932 + 11 p`（Rev 1 `C936`）取 11 個部件編號到 `$013B–$0145`。
2. 依 `rom.FACE_SLOTS` 把各部件的 4bpp 圖從 ROM 複製進 `$7E:8000` 的 16 × 16 sprite tile 緩衝（16 tile 一列）：部件 k 的來源 = 基底 + 編號 × 步距，兩列各 `width` bytes。部件 3、5、6、7、9、10 的 FF = 無；部件 10 的 0x80 bytes 以 0x40 為一列複製兩次。
3. 畫面用 metasprite 0（`$01:8A08` 指標表；count，再 count × (dx, dy, tile, attr)）：32 個 16 × 16 sprite，外側兩欄左右翻轉共用。夏候惇、胡軫、張飛、文醜（0x21、0x4A、0x91、0xB8）另外加 metasprite 0x150–0x153（`$01:8948`，畫在前面）。
4. 調色盤：OBJ 調色盤 0–1 = `$05:B033`（64 bytes；`$0139` bit 15 時 `$05:B133`），再把調色盤 1 換成 `$04:D2E8 + 32 p`（Rev 1 `D2EC`）。

武將詳細畫面上頭像在 (104, 31)，OBJ tile 在 VRAM 0x0000。224 人的部件組合互不相同。

## 8. 大地圖（mode 7）與地形

- `$05:8000`：bank `$19`（`$19:8000–$FFFF`，32 KB）原封不動複製到 `$7E:8000` 再送 VRAM 0：交錯的 word，低 byte = 128 × 128 tilemap，高 byte = 256 個 8bpp tile（每 tile 64 bytes，一 byte 一 pixel），全圖 1024 × 1024。平時用 matrix 0x400 縮成 1/4 顯示，放大時 1:1。
- 城標記（`$05:8039`）：國 c 的位置 (x, y) → tile 欄 2x − 1、列 2y − 1 起的 2 × 2：A = ((勢力 × 2) & 0x1E，≥ 0x10 再 + 0x10) \| 0xC0，四格 A、A + 1、A + 0x10、A + 0x11。城框（`$05:8097`）：周圍 12 格，tile 從 `$05:8102 + Y`（Y = 0／12／24 依城塞値 < 0x21／< 0x42／其他）。行軍中的部隊（`$05:8126`）：人物 +0 bit 7 = 1、bit 5–6 = 0、+1 bit 7 = 0 時，在 (+1, +2) 格畫部隊標記（開局沒有）。
- 調色盤（`$05:81B1`）：`$05:AF33` 256 色 → 再依月份 `$0127`（0 = 1 月）把 `$05:B1B3 + 64 m` 放到 0x20–0x3F；1/4 顯示時 `$05:B4B3 + 32 m` 放 0x40–0x4F、`$05:8243` 放 0xF0–0xFF；放大時 `$05:B633 + 32 m` 放 0x40–0x4F、0xF0–0xFF 全部填顏色 0x0F。之後 `$02:C9F2` 把視窗調色盤 `$02:CB1B`（Rev 1 `$02:CB22`）放進第 5、14、15 列（地圖用到 0x50–0x5E、0xF0–0xFF，所以畫面上是視窗色），玩家勢力的顏色會閃爍。
- 地形格 `$1D:D8CE`：64 × 64 bytes，index = 64 y + x（`$01:CD25`），一格 = 地圖 16 × 16 px = 國位置的單位。值：0 城（每國位置的左上 2 × 2，共 124 格）、1 不可通行（地圖邊與北方山地）、2 高山、3 低山、4 森林、5 平地、6 村落、7 水上。名稱 `$18:9D86`（2 字碼，`$00:BCC8`；0 與 1 是空白），移動等級 `$01:CD6D`（Rev 1 `$01:CD72`）= 00 FF 03 02 02 01 01 02（≥ 0x80 不可通行），`$01:CD42` 用游標查。
- **沒有獨立的戰術地圖**：出陣後部隊在放大的大地圖上移動、交戰（行軍フェイズ；部隊面板顯示所在格的地形名）。

## 9. Rev 0 與 Rev 1

63551 bytes 不同，大多是程式碼位移（bank `$01` 的載入程式、地形查表一帶往後 5 bytes）。資料上的差別：0x342 字形（緒 → 褚）、張嶷 讀音、典韋 的登用者；配置、國、勢力、國名、位置、頭像部件與頭像調色盤表往後 4 bytes。`Rom._find` 從程式碼裡的指令樣式取這些位址，兩版共用同一份解碼。

## 10. 未解

- 配置種類 1–5 的實際觸發條件（年、親族／推挙／登用的判定）與 +4；可選君主的選單表。
- 難易度 3 的升級（`$01:C8C1`／`$01:C8FF`）與 `$0810 + 5 f` 的修改。
- WRAM 人物 +2、+18–21，國 +17–20，勢力 +2–4 在遊戲中的用途；同盟、政策、控（預備兵）存在哪裡。
- 訊息字串表（bank `$1F`）、事件、劇本開場文字。
- 字碼 0x1FA–0x1FF 的半形合字、`$04:8000–$04:87FF` 的半高字對。
- 地形格沒有用模擬器驗證（遊戲只在行軍時以游標查表，沒有找到能穩定觸發的畫面）；目前的根據是程式碼（`$01:CD25` 的 index 計算）與 31 國位置全部落在 0 格、和地圖逐格對得上。
- 放大時的地圖調色盤與 2–12 月的調色盤只從程式碼解出，驗證只跑了 1 月、縮小顯示。
- 戰鬥規則、部隊移動與交戰的計算。
