# SFC 三國志III ROM 格式

KOEI，SFC，1992。檔案 `roms/Sangokushi III (Japan).zip`（原版）。

本文的偏移一律是**檔案偏移**（無 copier header 的 1.5 MB 映像）。CPU 位址寫成 `$bb:aaaa`，HiROM：檔案偏移 = `位址 & 0x3FFFFF`（`$C0:0000` = 檔案 0）。遊戲是編譯過的 C：參數放在 stack，結果在 DP `$00`，乘除法與指標運算走 `$C1:E91C`（16 位元乘）、`$C1:E968`（32 位元乘）、`$C1:EDF2`（表 + idx × n）、`$C1:EA07`／`$C1:EB61`（有號除／餘）等小函式。

## 1. 硬體與版本

| 項目 | 內容 |
|------|------|
| 標頭（`0xFFC0`） | `SANGOKUSHI 3`，map mode `31`（HiROM、FastROM），型別 `02`（ROM＋RAM＋電池），SRAM 32 KB，廠商 `C8`（KOEI），版本 0 |
| 向量 | native NMI `$00:8391`、IRQ `$8FE8`；emulation RESET `$8009` |
| 服務呼叫 | `$C0:8000`：stack 上第一個參數是服務號，跳表在 `$C0:9024`（`0x0B`／`0x0D` = 排 DMA 到 VRAM，`0x24` = memset，`0x4C` = 解壓縮） |
| Rev 1 | bank `$CA` 的表（人物、劇本、州名、寶物）位置相同；bank `$C1` 的資料整段後移 `0x18`（頭像調色盤 `0x1C19F`、合成表 `0x1E871` 等），壓縮指標表在 `0x7F3DE`，劇本標題與身分字串也搬了。`rom.py` 只支援原版 |

**Mesen**：savestate 只能在 exec callback 裡建立／載入；NMI handler 第一個指令 `$8391` 上 `loadSavestate` 會被拒絕，驗證腳本掛在第二個指令 `$00:8392`，而且建立 savestate 的那次 callback 不能馬上載入，要等下一次 NMI。這個遊戲對輸入時機很敏感：劇本 1 選劉備時差 1 幀，第一回合就會變成董卓攻鄴的 AI 戰鬥（`verify_tactical.py` 用的就是這條路），多 1 幀則停在指令選單（`verify_faces.py`、`verify_map.py` 的 `w1`）。

**操作**（幀數從開機算）：

| 步驟 | 輸入 |
|------|------|
| 標題 → 主選單 | `w1200 start w200 start w300` |
| 新遊戲 → 劇本清單 | `a w200`；劇本 n 先按 `down` × (n−1) |
| 選劇本（約第 2064 幀載入劇本） | `a w500` |
| 玩家人數 → 君主選擇（8 人一頁，劇本 1：公孫瓚 袁紹 劉備 韓馥／曹操 陶謙 董卓 孔融） | `up w30 a w300`；`right` × 2 = 劉備 |
| 決定君主、設定畫面 | `a w300` × 5 |
| 開局（約第 6100 幀到第一回合） | `a w1500` |
| 情報 > 自国 > 武将 > 一覧 > 武将畫面 | `down` × 3 `a`，`down a`，`a`，`a`（第二頁寶物：`a down a`） |

## 2. 壓縮資料（`0x7F3A7`）

491 個 3-byte 長指標（`$C7:F3A7`），指向 KOEI LZ 串流（`tools/koei_lz.py`；表塊在 `0x992F`）。

| entry | 內容 |
|-------|------|
| 2 | 解到 WRAM `$7F:E000`（未解） |
| 47–92 | 46 州的戰場資料，entry 47 + 州 index（§9） |
| 93–114 | 22 個和戰場同格式（1342 bytes）的資料，用途未解 |
| 115–119 | 戰場畫面的圖（tile） |
| 130–152 | 23 × 2560 bytes，未解 |
| 154–460 | 一般頭像 1–307，entry 153 + 頭像號（§7） |
| 461 | 大地圖的圖：751 個 4bpp tile，載到 VRAM tile `0x80`（§8） |
| 465 | 大地圖的州旗標：26 個 tile，載到 VRAM tile `0x370`（§8） |
| 其他 | 未解 |

## 3. 字型與文字

**字型**：16 × 16 1bpp，每字 32 bytes，由 4 個 8 × 8 tile 組成（左上、右上、左下、右下，每列 1 byte）。字 0–895 在 `0x1000`，字 896–1854 在 `0x140000`。

**文字碼**：2-byte 碼 `0x8140 + 字號`（大端）。`0x9140` 以上是跳脫碼：`0x91nn` 代表 `0x8200 + (nn − 0x40) × 0x100`，用來表示低位元組是 `00` 的碼（例：`0x9143` = `0x8500` = 世）。`0x8880`–`0x913F`（字號 ≥ 1855）顯示為空白。

| 字號 | 內容 |
|------|------|
| 0–60 | 符號、全形數字與英文 |
| 61–221 | 平假名、片假名 |
| 222 | Ⅲ |
| 223–1684 | 第一水準漢字（JIS 順序的子集） |
| 1685–1806 | 第二水準漢字 |
| 1807–1854 | 追加的人名、地名用字（郃 邕 顗 闓 譙 琮 伷 褚 邳 璝 釭 涪 鄴 笮 …） |

字號 → 字的對照在 `data/charset.txt`：把每個字形和系統字型依 JIS 順序做 DP 對齊，1807–1854 用 PC 版人名投票，再用 `tools/charset_sheet.py` 的對照圖目視修正。字號 9（ー）、17–18（第二組「」）、1697、1699、1741 仍不確定。異體：414 是「灌」字形放在「潅」的位置，1740 熙、1757 粱。

控制碼：`0A` 換行、`1B 'C' n` 換色、`00` 結束、printf 式的 `%d`／`%s`。半形片假名與 ASCII 是 cp932 單 byte。

**字串表**（3-byte 長指標）：劇本標題 `0x7E00B`（6 個）、身分 `0x1C8FD`（7 個：君主 軍師 将軍 武官 文官 在野 太守）、兵種 `0x1C935`（歩兵 騎馬 弩 強弩，後面的指標未解）。

## 5. 人物

### 5.1 人物表（`0xA8026`，532 × 30 bytes，依讀音排序）

遊戲直接讀 ROM（`$CA:8026`），不複製到 WRAM。

| 偏移 | 內容 |
|------|------|
| 0–1 | 頭像碼（LE16，§7） |
| 2 | 野心 << 6 \| 運 << 4 \| 冷静 << 2 \| 勇猛（各 0–3） |
| 3 | 未解 |
| 4 | 未解（`00`–`80`，只有高 4 位元） |
| 5–10 | 陸指、水指、武力、智力、政治、魅力 |
| 11 | 相性 |
| 12 | 義理 |
| 13 | 血縁群組（FF = 無） |
| 14 | 生年（西元）；年齢 = 年 − 生年 + 1（虛歲，劉備 189 年 29 歲） |
| 15–21 | 姓名，最多 3 個文字碼，補 0 |
| 22–29 | 讀音，半形片假名，補 0 |

### 5.2 劇本人物（531 × 4 bytes／劇本）

| 偏移 | 內容 |
|------|------|
| 0 | 兵士 / 100（FF = 無，WRAM 仍寫 25500） |
| 1 | 身分：bit 7 = 旗標（君主與部分武将，未解），低 7 位元 0 君主、1 軍師、2 将軍、3 武官、4 文官、5–7 不屬勢力（6、7 的意義未解）；FF = 不登場 |
| 2 | 忠誠（FF = 無） |
| 3 | 所在州 index（0–45，FF = 無） |

人物 531（貂蝉）不在劇本表裡（載入器只跑 531 人）。

**WRAM 人物**（`$347E + 30 i`，`$C7:49FF`）：

| 偏移 | 內容 |
|------|------|
| 0–1 | 串列指標 |
| 2–3 | 兵士 = 劇本 +0 × 100 |
| 4–5 | 寶物 bit：持有者 = 此人的寶物 i 設 bit i |
| 6–7 | = 人物表 +2–3 |
| 8 | 身分 FF 時 = `10` |
| 10 | = 人物表 +4 |
| 12 | 身分 & 7F（身分 FF 時為 0） |
| 13、14 | 相性、義理 |
| 15 | 忠誠 |
| 16 | 所在州 |
| 17 | 勢力：身分 0–4 = 所在州的勢力，其他 FF |
| 18、19 | 1、FF |
| 21、22 | 訓練、士気：身分 0–3 且兵士 ≠ 0 時 = 劇本州 +28／+29，否則 0 |

## 7. 頭像

`$C1:65D7`（頭像碼, 欄位, 旗標）：40 × 48 = 5 × 6 個 4bpp tile，寫到 VRAM tile `0x20 + 30 × 欄位`（武将畫面用欄位 1 = VRAM `0x7C0`），調色盤 `0x1C187`（BG 調色盤 4，全員共用）。

| 頭像碼 | 內容 |
|------|------|
| FFFF | 隨機 |
| 0、> 307 | 當作 1 |
| 1–307 | 一般頭像：entry 153 + 碼，960 bytes 解到 `$7F:E000` 再 DMA |
| bit 15 | 合成頭像 `$C1:6477`：5 個部位直接從 ROM DMA 到 VRAM |

**合成頭像**：

- 型 t（0–12）= bit 14 為 0 時 `0x1C538` 的 word[碼 & 7]，為 1 時 `0x1C52E` 的 word[碼 & 7] + 8。
- 部位 0–4 的變體 = 碼的 bit 7–9、bit 10、bit 11–12、bit 3–4、bit 5–6（`$C1:5ED9`）。bit 13 未用（所有人都是 0）。
- 部位 p 的圖：`0x1E859 + 15 t + 3 p` 的長指標，未壓縮 4bpp tile；每個變體佔該部位 tile 數 × 32 bytes。

部位 p 畫在哪些格（5 × 6 格，`$C1:6058`）：

- 位置：`0x1C3A8 + 10 t + 2 p` 的 LE16 = x × 10 + y。
- p < 3：`0x1C326 + 10 t + 2 p` = 寬 × 10 + 高，一個矩形。
- p = 3：`0x1C42A + 12 t`；p = 4：`0x1C4C6 + 8 t`。第一個 word 是矩形數，後面每個 word 的 4 位十進位數字 = x、y、寬、高（相對於位置）。
- tile 依矩形順序、逐列排放。

例：型 0 的部位 0 = (1, 2) 起 3 × 1、部位 1 = (2, 3) 1 × 1、部位 2 = (1, 4) 3 × 1、部位 3 = 頭部 16 格、部位 4 = 下方 7 格，合起來剛好 30 格。各部位存的變體數 6、2、4、4、4。部位名稱（目、鼻、口、頭、肩）是看圖推測。532 人中 221 人用一般頭像、311 人用合成頭像（11 種型，型 5、9 沒人用）。

一個畫面大小：BG2，tilemap 在 VRAM word `$1400`（32 格寬，地圖從第 1 欄開始），tile 在 VRAM byte `0x8000`。

| 項目 | 位置 |
|------|------|
| tilemap | `0x2E1AC`，30 × 28 個 LE16（未壓縮） |
| 圖 | entry 461 → tile `0x80`–`0x36E` |
| 調色盤 | BG 調色盤 2：`0x1C067`；水面顏色循環，另一格是 `0x1C087`（`0x1C047`、`0x1C0A7` 等可能是季節版，未驗證） |
| 州旗標 | `$C1:5C7F`：州 k 的格 = `0x1D0CF + 2 k`（欄, 列）；tile = `0x0C00 \| (0x370 + 旗色)`，旗色 = header +4 + 勢力，無勢力 `0x19`；圖 = entry 465，調色盤 3 = `0x1C167` |

## 9. 戰場（戰術地圖）

戰場資料 = entry 47 + 州 index（鄴 = entry 53 已用遊戲驗證），1342 bytes，解到 WRAM `$7E:C104`：

| 偏移 | 大小 | 內容 |
|------|------|------|
| 0 | 22 × 21 | A 層：每格的地形圖號；`$C3:56BE` 以 `$C104 + 22 y + x` 讀取，`3A`／`3B` 依 `$7E:CD2C`（季節？）換成 `3C`／`3D`／`46` |
| 462 | 22 × 20 | B 層：推測是地形種類（`03`、`05`、`0B`、`0C`、`13`、`17`、`19` …） |
| 902 | 22 × 20 | C 層：推測是佈陣區（`06`、`08`、`32`、`33`、`42`、`7F`、`FF` …）；戰鬥開始後會被改寫 |

畫面是等角視角：BG2 tilemap 64 × 64，每格畫成 2 × 2 tile，兩張 tilemap 緩衝在 `$7F:C000` 與 `$7F:E000`。`$C3:5B0F` 依格子與相鄰格算出 8 個 tile word，`$C3:5EC3` 寫入緩衝；圖在 entry 115–119。這段的 tile 選擇規則還沒解，`export.py` 只輸出三層格子的 CSV 與 B 層示意圖。
