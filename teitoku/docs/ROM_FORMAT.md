# SFC 提督の決断 ROM 格式

KOEI，1992，SFC。檔案 `roms/Teitoku no Ketsudan (Japan).zip`（原版）與 `roms/Teitoku no Ketsudan (Japan) (Rev 1).zip`。美版 `P.T.O. - Pacific Theater of Operations (USA).zip` 只拿來參考。

本文的偏移一律是**檔案偏移**（無 copier header 的 1.25 MB 映像）。CPU 位址寫成 `$bb:aaaa`，LoROM：檔案偏移 = `(bb & 0x7F) × 0x8000 + (aaaa − 0x8000)`。WRAM 位址寫 `$7E:xxxx` 或省略 bank 寫 `$xxxx`。「推測」表示沒有獨立驗證過。

## 1. 硬體與引擎

| 項目 | 內容 |
|------|------|
| 標頭（`0x7FC0`） | `TEITOKU NO KETSUDAN`，map mode `20`（LoROM），ROM＋RAM＋電池，SRAM 32 KB；版本 byte `0x7FDB`：原版 0、Rev 1 為 1 |
| 向量 | native NMI `$00:8385` |
| 程式 | C 編譯的 65816 碼。區域變數在堆疊（`LDX #n; JSL $01:F030` 開框），乘除、指標運算是 `$01:Exxx`／`$01:Fxxx` 的小函式 |
| 服務分派 | `JSL $00:8000`，第一個引數是功能號：`0x4C` 解壓 LZ 到 `$7F:8000`、`0x17` 記憶體複製、`0x03` 載入調色盤 ⋯ |
| printf | `$06:C39A`（格式字串 24-bit 指標＋引數），核心 vprintf `$06:BD03`，逐字輸出 `$06:B2C4`。`%s` 的引數佔 4 bytes（24-bit 指標＋1 byte 雜值），`%d` 2 bytes，`%ld` 4 bytes。驗證腳本都掛在 `$06:BD03` 上讀引數 |

### 操作序列（`tools/sequences.py`）

標題 `w1800 start start` → 選單（新しくゲームを始める）`a` → 劇本選單（9 個，↓ 選）`a` → 何人でプレイ（0–2，預設 0）`up a` 選 1 人 → 担当（日本軍／連合国軍，↓ 選）`a` → 難易度 `a` → Y/N `a`（此時跑劇本載入 `$0B:9A5A`）→ 地圖與目標說明 `a` → 予算案（`b b b start a start`）→ 将校データ：每位提督的四項能力隨機跳動，按鍵停下再按 Y，每人 2 下（至多 20 人）→ 主畫面（約第 9900 幀）。

- 主畫面選單：作戦 待機 哨戒 命令 情報 資料 其他（`b` 關掉下拉選單後左右移動，`a` 開啟）。資料：国力 人材 他国 艦船（修理中／建造中／予備）基地 作戦目標 勝利条件；命令：艦隊 基地 艦隊編成 艦船処分。`select` 開設定（名前変更、ウエイト、HEX 表示、戦闘デモ、記録）。
- 清單翻頁：艦船清單按 `a`；基地、他国清單按 `r`（`right` 是切換欄位組）。
- 劇本 1 日本軍一開始就是陸軍要求的作戦会議（強制，要選目標才能結束）；劇本 2 連合国軍一開始就是珍珠港的戰鬥畫面。驗證多用劇本 3（珊瑚海）日本軍，主畫面沒有插入事件。
- 按鍵按住 10 幀；選單之間等 300 幀，主畫面的游標移動等 30–60 幀即可。

## 2. 版本差異

- **Rev 1**：只有程式碼改了零星位置（約 760 處、7 萬 byte，多在 bank 01、04–05 等程式區），LZ 指標表從 `0x4F3EF` 移到 `0x4F3FB`（+0xC），433 個指標內容相同。資料區（`0x10000–0x18000`、`0xA0000` 之後）與本文用到的所有表、程式位址（`$0A:B2A9`、`$0B:9A5A`、`$06:BD03`、`$01:F06B` ⋯）都一樣。夾在程式碼之間的 printf 格式字串會跟著程式碼移動：`$06:FDE1` → `$06:FDA8`（−0x39），bank `$0E` 的艦隊面板字串 `$0E:EEE5–EFC9` +0x41、基地詳細的 `$0E:EFE3–F047` +0x5A；bank `$0A`、`$07`、`$0F` 用到的不變（`rom.REVISIONS[1]["strings"]`，驗證腳本攔 printf 時用它換算）。`rom.py` 以 `0x7FDB` 判定版本，兩版都支援；`Rom.scenario_image` 兩版 9 劇本完全相同。
- **美版 P.T.O.**：同樣 LoROM 1.25 MB，指標表 `0x4F3AE`（434 筆），文字是英文，未解析。

## 3. 壓縮資料

KOEI LZ，表在 `0x18C8`，解壓程式 `$00:9A25`（包裝 `$00:9896`：DP `$54` = 目的低位 `0x8000`，`$56–$58` = 來源 24-bit），解到 `$7F:8000`。用共用的 `tools/koei_lz.py`。

長指標表 `0x4F3EF`（Rev 1 `0x4F3FB`），433 筆（`$09:F3EF`）：

| 編號 | 大小 | 內容 |
|------|------|------|
| 0–53 | 960 | 頭像 40 × 48（§11） |
| 54–166 | 2048 | 艦船圖 128 × 32，每個艦級一張（§12） |
| 167–185 | 3072 | 場景圖 128 × 48（港口、飛機等，§12） |
| 186–382 | 512 | 大地圖的 32 × 32 px 區塊，186 = 海面，187–382 = 陸地區塊 1–196（§13） |
| 383–390 | 5688 | 劇本 2–9 的修補（§5） |
| 391–408 | 768／4608 等 | 未解（推測戰鬥畫面用的圖） |
| 409–412 | — | 不是 LZ（解壓失敗），未解 |
| 413–432 | 雜項 | 未解 |

不在表裡的串流：`0xA4515`（`$14:C515`，10144 bytes）= 世界地圖的 317 個 tile（§13），載入劇本後由 `$06:A112` 解壓。標題畫面的圖另有串流（`$1E:EF00` 等），未整理。

## 4. 字型與文字

- **字型** `0x118000`（`$23:8000`），1036 個字形，每個 16 × 16 1bpp、32 bytes（左上、右上、左下、右下 4 個 8 × 8）。第 1024 個以後在下一個 bank `$24:8000`（檔案上仍連續）。字形 0–2 是符號（々 ～ →），3–1022 是 JIS 第一水準漢字的子集（JIS 順），1023–1035 是第二水準（亢 厰 弩 殲 澤 熕 纒 翔 膠 蛟 蟠 驤 勃）。字形 → 字的對照在 `data/charset.txt`（用其他光榮作品的字型逐點比對 528 字，其餘依 JIS 順序與系統字型對齊後逐一目視修正）。字型由 `$01:F06B` 複製（呼叫自 `$06:B643`）。
- **二字節碼** `0x8140 + g`（big-endian）= 字形 g，到 `0x854B`；`0x854D–0x913F` 畫字形 0；低 byte 為 0 的碼（`0x8200`、`0x8300` ⋯）不能出現在字串裡，寫成跳脫碼 `0x9140 + k` = `0x8200 + 0x100 k`（`$06:B5B0`）。
- **一字節碼**：ASCII；JIS X 0201 半形假名 `0xA1–0xDF` 預設畫成**平假名**，`ESC K`（`1B 4B`）之後畫片假名，`ESC H`（`1B 48`）切回；`ﾞ ﾟ` 是濁點、半濁點（`rom.py` 合成成一個字）。`ESC F` 切換日期字（`0`=年 `1`=月 `2`=日）；`ESC C n` 顏色；`0x0A` 換行、`0x09` tab。半形假名用的是另一套字型，沒有經過 `$01:F06B`。

|------|------|------|
| `0x101A6` | `$7E:205A` | `0x2291` |
| `0x13567` | `$7E:42EB` | `0xB8E` |
| `0x142E4` | `$7E:4E79` | `0xC92` |
| `0x10000` | `$7E:5B0B` | `0x1A6` |

## 6. 艦船（22 bytes）

| 偏移 | 內容 |
|------|------|
| +0–2 | 名稱指標（bank 02，`{ESC K}漢字 讀音{ESC H}`，空白前是艦名、後是讀音；盟軍艦只有片假名） |
| +3 | 艦種（0 潜水艦 1 新型潜水艦 2 駆逐艦 3 新型駆逐艦 4 巡洋艦 5 新型巡洋艦 6 戦艦 8 弩級戦艦 9 新型戦艦 10 軽空母 12 正規空母 13 新型空母；14 兵員、15 燃料是輸送船的名稱，不出現在艦船表）；名稱指標表 `0x1C1A3`（`$03:C1A3`），顏色表 `$03:C263` |
| +4 | 所屬艦隊號（陣營內 1 起算，0 = 無） |
| +5 | 対艦砲撃力（推測：工廠設計畫面的欄位順序「対艦砲撃力 対空砲撃力 装甲 速度 搭載数」與 +5–+9 一致，戰艦大、驅逐艦小） |
| +6 | 対空砲撃力（推測，同上） |
| +7 | 装甲（推測，同上） |
| +8 | 速度（節）：艦隊面板的最高速度 = 艦隊中最慢的艦 |
| +9 | 搭載数（推測：空母 63–80，戰艦、巡洋艦 2–6） |
| +A／+B／+C | 戦闘機／攻撃機／偵察機（艦隊面板三個圖示的合計） |
| +D | 兵員（艦隊面板「兵員」= 各艦 +D ＋ 兵員輸送船的載量） |
| +E／+F／+10 | 未解（0–99，劇本間會變，推測練度、耐久之類） |
| +11 | 完成月份（從昭和 16 年 11 月起算的月數）；遊戲開始時減去經過月數，≤ 0 的建造中艦船直接完成 |
| +12 | 未解（多為 0） |
| +13 | 艦級（同型艦相同；日本 1–0x2E、盟軍 0x34–0x6A），決定艦船圖 |
| +14 | bit 1 = 建造中（且 +11 > 經過月數）；其他位元未解 |
| +15 | bit 0 = 陣營（0 日本、1 連合国）；bit 2 = 已沉沒（疾風、伊23 在劇本 3）；其他位元未解 |

「予備艦船」清單 = 日本艦中 +4 = 0、非建造中、未沉沒者；「建造中艦船」= 建造中者（`verify_tables.py`）。

## 9. 陣營（59 bytes）、提督（35 bytes）、他國（14 bytes）

- **陣營**：+0 編號、+1 名稱（「日本」「連合国」，NUL 結尾）、+2C／+2F／+32 三個基地指標（推測作戦目標）、+35 司令部基地（1 起算）；預算、資源備蓄等其餘欄位未解（`sides.csv` 附原始 bytes）。
- **提督**：+0 姓名（日本軍漢字，名與姓以空白分隔；盟軍 `{ESC K}W.F.ハルゼイ{ESC H}`）；+1D–+20 艦船、航空、作戦、勇猛：**開局時亂數產生**（`$0B:9620`：4 個 0–98 的亂數正規化，前三項 = r × 98 / 和 + 1，第四項 = 0x66 − 前三項和），ROM 裡沒有；+22：低 5 bit = 指揮的艦隊號，bit 7 = 不登場（山本五十六在劇本 7 起、山口多聞在劇本 5 起、フィリップス、ドールマン ⋯），bit 5／bit 6 只出現在英國的フィリップス、荷蘭的ドールマン（推測外國籍）。頭像見 §11。
- **他國**：+0–2 名稱指標；+3 同盟（1 日本 2 連合 3 中立）；+4 對日、+5 對連合的態度；+6–7 未解；+8–+C 五個數值（未解）；+D 旗標（他國畫面的「新戦 レーダ 長爆」三欄，推測 bit 0 レーダー、bit 1 新型戦闘機、bit 3 長距離爆撃機）。

## 11. 頭像

`$0A:B2A9(side, index)`：index 100–105 換成 (index − 80) + 20 × side；side 0 用圖 = LZ 編號 index、調色盤號 = `0x569B9[index]`（`$0A:E9B9`，27 bytes）、調色盤 = `0x14FEF + 32 × 號`（`$02:CFEF`）；side 1 先 index −= 20，圖 = 編號 27 + index、調色盤號 `0x569D4[index]`、調色盤 = `0x152CF + 32 × 號`（`$02:D2CF`）。圖是 40 × 48，5 × 6 個 4bpp tile 逐列排，寫進 VRAM `$7A00`，調色盤進 CGRAM 第 5 列。

- 提督 i（0–39）呼叫 (i // 20, i)：日本 0–19 → 頭像 0–19，盟軍 20–39 → 頭像 27–46（`Rom.admiral_face`）。
- 其他 14 張：20–25／47–52 是 index 100–105（作戦会議等場面的人物），26、53 呼叫者未找到。身分沒有名字，依服裝分組（推測）：20 陸軍（灰髮、口髭）、21 海軍、22–23 陸軍、24–26 飛行員；47 陸軍（迷彩鋼盔）、48–50 海軍、51–53 飛行員。
- 遊戲沒有單一的頭像碼（以 (side, index) 選圖），kaodata 不寫 `code`。

## 12. 艦船圖、場景圖

- **艦船圖**（`$06:9D30`）：艦級 c < 0x34 → LZ 編號 115 + c（`$09:F54B`），c ≥ 0x34 → c + 2（`$09:F491`）。128 × 32（16 × 4 tile），tilemap `$06:FAA3`（調色盤列 6），調色盤 `0x1550F`。主畫面艦隊面板在艦隊**出海**時顯示旗艦的艦船圖。
- **場景圖**：編號 167–185，128 × 48（16 × 6 tile），由 `$06:A7xx` 載入（圖 `$09:F5E4 + 3k`、調色盤 `$02:D58F + 32k` = `0x1558F`）。艦隊**在港**時面板顯示場景圖而不是艦船圖（劇本 1：日本在クレ → 167、盟軍在ハワイ → 169）。基地與場景圖的對應、k ≥ 1 的調色盤是否就是 `0x1558F + 32k` 未驗證；168–185 的一部分用這個寬度畫出來是亂的，推測不是 16 × 6 排列或是戰鬥畫面用的零件。

## 13. 地圖

- **世界地圖**（劇本說明、目標選擇）：tilemap `0x131A7`，32 × 15 個 word（tile 0x2C0–0x3FC、調色盤 7），在 VRAM `$E200`（BG tilemap `$E000` 的第 8–22 列）；tile = 串流 `0xA4515` 解壓的 317 個 4bpp tile，放在 VRAM `$9800`（字元基底 `$4000` 起的第 0x2C0 個）；調色盤 `0x66E8E`（CGRAM 第 7 列）。256 × 120 px。
- **大地圖**（作戦→移動、目標選擇的放大框，`$0A:B6xx`）：32 × 16 個 32 × 32 px 區塊 = 1024 × 512 px；地圖座標 120 = 1 區塊（基地、艦隊座標都用這個單位，X 約 0–3700、Y 約 0–1900）。區塊 (bx, by) 的內容（`$0A:B42A`）：位元表 `0x569EF`（`$0A:E9EF`）每列 4 bytes（MSB 先），該位元 0 → 海面（LZ 186）；1 → 陸地區塊 n = `0x56A2F[by]`（`$0A:EA2F`，LE16，前面各列的陸地數）＋ 本列到 bx 為止（含）的 1 的個數，LZ 編號 186 + n。共 196 個陸地區塊。調色盤同世界地圖。顯示時取艦隊所在區塊周圍 3 × 3。大地圖上已經畫好基地的兩字母代號。

## 14. 戰鬥畫面（未解）
