# SFC 信長の野望・覇王伝 ROM 格式

KOEI，1993，SFC。檔案 `roms/Nobunaga no Yabou - Haouden (Japan).zip`（另有 `(Rev 1).zip`）。

本文的偏移一律是**檔案偏移**（無 copier header 的 2 MB 映像）。CPU 位址寫成 `$bb:aaaa`，HiROM：檔案偏移 = `位址 & 0x3FFFFF`（`$C0:0000` = 檔案 0）。程式位址都是原版（Rev 0）的；Rev 1 搬動了大部分的表與程式，資料表的兩版偏移見 `rom.OFFSETS` 與 §12。「推測」表示沒有獨立驗證過。

## 1. 硬體與操作

| 項目 | 內容 |
|------|------|
| 標頭（`0xFFC0`） | `Nobunaga Haouden`，map mode `31`（HiROM），ROM 2 MB（`0B`），SRAM `05`；版本 byte `0xFFDB` = 0／1 |
| 向量 | native NMI `$00:848D`（Rev 1 `$00:8491`），第一個指令是 SEI |
| 劇本載入 | `$C3:0AD1` 把劇本映像與共用區複製到 WRAM（§5） |

Mesen 的 savestate 只能在 exec callback 裡建立／載入，驗證腳本都掛在 NMI handler 的第二個指令上（`tools/replay.py` 從 ROM 的 NMI 向量算出）；載入後第一輪不生效，第一項都做兩次再丟掉。按鍵要按住約 10 幀，太短常被吃掉。

**操作序列**（`tools/drive.py` 語法，幀數從開機算起）：

- 劇本 1、龍造寺隆信，到第一回合主畫面（約第 7000 幀）：
  `w1500 start:10 w200 a:10 w200 a:10 w60 a:10 w60 a:10 w60 a:10 w60 a:10 w60 a:10 w400 a:10 w200 a:10 w900 a:10 w300 right:10 w30 a:10 w1500 a:10 w1200`
  （標題 → 新しく始める → 設定畫面各列 a → 実行 → 選大名地圖，游標從島津移到龍造寺 → 確認）
- 選劇本：設定畫面第一列是劇本，`right` 換劇本，之後各列 a、最後在「実行」上 a 進入選大名畫面（`verify_scenarios.py`）。
- 電腦對戰觀戰：設定成 1551 年、好戦的、初級、玩家大名 0 人、他国合戦「見る」：
  `w1500 start:10 w200 a:10 w300 a w60 a w60 right w60 a w60 a w60 left w60 a w60 left w60 a w60 a w100 a:10 w100 a:20 w400`
  之後電腦自己進行，第一場合戦（地圖 134）約在第 20400 幀載入（`verify_battle_maps.py`）。Rev 1 電腦走法不同：約第 18800 幀 `$7E:8733` = 63（今浜），約第 19800 幀變成 131（今浜的城類 `0x83` 的無城地形圖），戰場約在第 19900 幀載入、用調色盤組 2。

## 2. 壓縮資料

KOEI 的 LZ，直接用共用的 `tools/koei_lz.py`（`find_tables` 找到的表：原版 `0xA0D9`，Rev 1 `0xA0D3`，`rom.py` 用這個值判斷版本）。資料用一張 810 個 3-byte 長指標的表（原版 `0x7BD84`，Rev 1 `0x7C422`）指到各個 LZ 串流，下面稱「LZ 項目 n」：

| 項目 | 內容 |
|------|------|
| 14 | 大地圖 tile（4bpp，18432 bytes，載到 VRAM `0x8400`） |
| 15 | 大地圖 tilemap（96 × 32 LE16） |
| 93–440 | 專屬頭像 348 張（每張 960 bytes 的 4bpp tile） |
| 441 | 戰場 tile（23552 bytes，載到 VRAM `0x8200`） |
| 466–608 | 戰場地圖 0–142（每張 1840 bytes） |
| 609 | 戰場上緣半格，每張地圖 40 bytes |

## 3. 字型與文字

- **字型**在 `0x1F0000`，1808 字，每字 32 bytes：16 × 16 1bpp，4 個 8 × 8（左上、右上、左下、右下，每列 1 byte）。字的排列是 JIS X 0208 順序的子集：符號、英數、假名、第一水準漢字（255–1762）、第二水準漢字（1763–1803）。字碼表 `data/charset.txt` 是先和項劉記／三國志III／三國志IV 的字型逐點比對（1408 字），其餘再和系統日文字型比對、人工檢查並對照人名、城名、家宝名。
- **文字**：big-endian 2-byte 碼 `0x8140 + 字號`。低 byte 會是 `00` 的碼改寫成 `0x9140 + k`（= `0x8200 + 0x100 k`）。`0x81–0x91` 以外的 byte 是控制碼（`rom.Rom.text` 顯示成 `[xx]`），`00` 結尾。
- **合字**：4 字的姓用 3 格畫：1804 1805 1806 = 長宗我部、1807 1805 1806 = 香宗我部（`rom.LIGATURES`）。
- **名稱表**：3-byte 長指標表，各指到 `00` 結尾的字串：

| 表 | 原版 | Rev 1 | 筆數 |
|----|------|-------|------|
| 國 | `0x297EA` | `0x2B17D` | 64 |
| 官位 | `0x28896` | `0x2A229` | 226 |
| 家宝 | `0x29226` | `0x2ABB9` | 120 |
| 合戦 | `0x29ADE` | `0x2B471` | 15 |
| 能力名 | `0x2A94C` | `0x2C2DF` | 8（政治 戦闘 智謀 采配 野望 気合 勲功 知行） |
| 姫 | `0x3A8AC` | `0x3B130` | 93 |
| 地形 | `0xA5FE4` | `0xA6378` | 15（平地 低山 川 森 城 道 城門 海 橋 砂地 湿地 高山 町 田畑 馬防柵） |

官位表裡有「佑親佑」這種看起來奇怪的項目，是遊戲資料原樣。

## 4. 人物 Id

人物 Id 0–819（139、140、456 沒有用到，共 817 人）。沒有獨立的人物基本表：每個劇本映像各帶一份開局人物（§5.2），另外每劇本有一張後登場人物表（§5.5）。`rom.Rom.person_master` 依劇本 1→3、開局→後登場的順序取每個 Id 第一次出現的記錄；同一 Id 在不同劇本可能改名（例：長尾景虎→上杉謙信、松平元康→徳川家康，共 5 人），`persons.csv` 的「其他名」列出。人物 Id 同時是頭像碼（§9）。

## 5. 劇本

3 個：1551、1568、1582 年。開始遊戲時 `$C3:0AD1` 把劇本 s 的映像（0x6303 bytes）複製到 `$7E:2000`，共用區 `0xB6303`（0x42D bytes）複製到 `$7E:8303`：

| 劇本 | 原版 | Rev 1 |
|------|------|-------|
| 1（1551） | `0xB0000` | `0xB0000` |
| 2（1568） | `0xB672F` | `0xB672F` |
| 3（1582） | `0x9900C` | `0x986EC` |

映像內的配置（WRAM 位址 = `0x2000 + 映像偏移`）：

| WRAM | 內容 |
|------|------|
| `$7E:2000–$7E:20E0` | 開頭區（未解；`$2020` 起像是一串 3-byte 資料） |
| `$7E:20E1` | 大名 64 筆 × 39 bytes（§5.3） |
| `$7E:2AA1` | 人物 460 筆 × 39 bytes（§5.2） |
| `$7E:70B5` | 城 110 筆 × 38 bytes（§5.1） |
| `$7E:8109–$7E:8302` | misc 區（未解，推測含姫的資料） |
| `$7E:8303–$7E:872F` | 共用區（未解；`0x180` 以後開局時會改寫） |

表之間用 WRAM 位址（LE16，`$7E:xxxx` 的低 16 位元）互相指，0 = 無。

`verify_scenarios.py`：3 劇本在選大名畫面時 WRAM 與映像逐 byte 比對，不同之處只有開局才設定的欄位（人物 +30 低 4 位元、大名 +35／+37、城 +35、共用區 `0x180` 以後）。

## 6. 合戦

合戦名稱表 15 筆；`$C5:F4DE`（檔案 `0x5F4DE`，Rev 1 `0x5F961`）15 個 LE16 = 各合戦對應的城（`$C5:8171` 讀）：沖田畷→原、耳川→都於郡……。攻打這些城時有機會變成合戦，使用戰場地圖 `0x6F + i`（111–125，`$C5:8168`）。

## 7. 城類（無城戰場）

`$C2:8148`（檔案 `0x28148`，Rev 1 `0x29ADB`）110 個 LE16，每城一個城類：`0x7E`（43 城）、`0x83`（56 城）、`0x85`（5 城）、`0x89`（6 城）。用法見 §10.3。

## 8. 大地圖

- 一層 BG2（16 × 16 tile），tilemap 是 LZ 項目 15：96 × 32 個 LE16（SNES tilemap entry：tile 號、調色盤、翻轉）；tile 號 n 的 16 × 16 tile = 8 × 8 tile n、n+1、n+16、n+17。
- Tile 是 LZ 項目 14，載到 VRAM `0x8400`，BG 字元基底 `0x8000`，所以 tile n 在項目內的偏移 = `32 n − 0x400`。
- 調色盤 2 與 3：原版 `0xA8CED`、`0xA8D0D`（Rev 1 `0xA9081`、`0xA90A1`），各 16 色。調色盤 3 的第 13、14 色每幾幀互換（水面動畫）。
- 遊戲把解壓後的地圖放在 WRAM `$7F:E800`，再依城主把城的圖示格重畫（換調色盤或換成旗 tile，tile `0x10A`、`0x10E`、`0x120`）。
- **城的位置**：`$C5:ED80`（檔案 `0x5ED80`，Rev 1 `0x5F205`）110 筆 × 2 bytes（x、y），`$C2:4BA1` 讀，地圖格寫入程式 `$C2:3636` 用 (x + 1, y + 1)；本城圖示另佔上面一格。`map_castles.png` 標出全部 110 城。

## 9. 頭像

40 × 48（5 × 6 個 4bpp tile，逐列 960 bytes），由 `$C1:187F(…, 頭像碼)` 組好放到 OBJ tile（VRAM `0x2400`）。調色盤只有一組：原版 `0xA8C6D`（Rev 1 `0xA9001`）16 色，`$C1:08CC` 複製到 OBJ 調色盤 7（CGRAM `0x1E0`）。

頭像碼 → 來源（`rom.Rom.face_source`）：

| 頭像碼 | 來源 |
|--------|------|
| 0–0xD2 | 專屬頭像 12 + 碼 |
| 0xD3–0x36D | 表 `0x1B9EC`（Rev 1 `0x1C2D9`）的 LE16 w：bit 15 = 1 → 專屬頭像 12 + (w & 0x7FFF)；否則組合臉，組 = 依頭像碼（< 0x160：0、< 0x1EC：1、< 0x278：2、< 0x304：3、其餘 4），碼 = w |
| 0x36E–0x379 | 專屬頭像 碼 − 0x36E（0–11） |
| 0x37A–0x391 | 組合臉，組 5，碼 = 表 `0x1B9A4`（Rev 1 `0x1C291`）[碼 − 0x36E] |
| 0x392–0x397 | 專屬頭像 碼 − 0x24B |
| 0x398–0x399 | 程式沒有處理（沿用堆疊上的舊值，畫出前一張），不算有效頭像碼 |
| 0x39A–0x3A0 | 專屬頭像 碼 − 0x24D |

「專屬頭像 n」= LZ 項目 93 + n（n = 0–347，全部都有用到）。有效頭像碼共 927 個。

**組合臉**（`$C1:1835`）：6 組 × 5 部位，每部位 5 款。部位表 `0x1B0A7`（Rev 1 `0x1B994`）：部位 p、組 g 在 `+48 p + 6 g`，3 個 LE16 = 格遮罩（格 0–14，bit 15 = 格 0）、格遮罩（格 15–29）、每款的 tile 數。Tile 池在 `0x17908B + 0x12C0 g`（兩版相同），依部位 0–4、每部位 5 款依序排，每款依格號順序放遮罩中為 1 的格。碼的第 3p 位元起 3 個位元 = 部位 p 用第幾款（0–4）。每組 5 個部位的格恰好蓋滿 30 格、互不重疊。

kaodata 資料集 `nobu5-sfc`：6 個 variant（= 組），slot `part0`–`part4`（部位 1–5）各 5 款；348 張專屬頭像；817 個人物（人物 Id = 頭像碼）。

## 10. 戰場地圖

### 10.1 格式

- LZ 項目 466 + m（m = 0–142）：40 欄 × 23 列的六角格，**逐欄**存放，每格 2 bytes（地面碼、覆蓋碼／`FF` = 無）。奇數欄往下錯半格（8 px）。
- LZ 項目 609：每張地圖 40 bytes = 20 組（地面碼、覆蓋碼），是奇數欄上方那半格（只畫下半部，在第 0 列 tile）。
- 每個碼是 2 × 2 tile 的 metatile：地面碼 c → metatile `meta[c]`、翻轉 `flip[c]`；覆蓋碼 c → metatile `80 + overlay_meta[c]`、翻轉 `overlay_flip[c]`（翻轉 bit 0 = 水平、bit 1 = 垂直）。Metatile 表每筆 4 個 LE16 tilemap entry（左上、右上、左下、右下）。

| 表 | 原版 | Rev 1 |
|----|------|-------|
| 地面 meta | `0xACD5A` | `0xAD0EE` |
| 地面 flip | `0xAD14E` | `0xAD4E2` |
| 覆蓋 meta | `0xACF5A` | `0xAD2EE` |
| 覆蓋 flip | `0xAD34E` | `0xAD6E2` |
| metatile | `0xAD54E` | `0xAD8E2` |
| 調色盤 3 組 × 0x60 bytes | `0xA9353` | `0xA96E7` |

- Tile = LZ 項目 441，載到 VRAM `0x8200`（字元基底 `0x8000`）；調色盤組 k 的 0x60 bytes 放到 CGRAM 調色盤 2–4。
- 遊戲把兩層組成 WRAM `$7F:0000`（地面）與 `$7F:20D0`（覆蓋），各 84 × 50 個 entry（四周多 2 格邊框）。`rom.Rom.battle_tilemaps` 產生同樣的配置（不含邊框）。

### 10.2 載入

戰場載入程式在 bank `$CA`，從 `$7E:8733` 讀地圖編號（`$CA:36D8`、`$CA:3BDE`、`$CA:3C1F` 三處 `LDA $7E8733`）。`verify_battle_maps.py` 把這三處換成 `LDA #m`，讓遊戲自己解壓並組出每一張地圖。

### 10.3 地圖編號的選擇

| 地圖 | 用途 |
|------|------|
| 0–109 | 地圖上畫有一座城；編號 = 城 Id（推測：依城表順序與圖上的城對應，未逐張在遊戲中確認） |
| 110 | 特殊；`$C1:024C`（某條件下寫 `0x6D`）、`$C5:8925`／`$C5:8933`、`$C7:14F2` 也會寫 `$7E:8733`，地圖 110 何時使用未解 |
| 111–125 | 15 場合戦（§6） |
| 126–142 | 無城地形圖，`$C5:8330` 依城類（§7）選：`0x7E` → 126 + 亂數 0–2；`0x83` → 131 + 亂數 0–1；`0x85` → 表 `$C5:F51A`[i]（`133 135 134 133 136 134`）；`0x89` → 137 + i。i（0–5）的來源未解；129、130 不經過這段程式，使用時機未解 |

Rev 1 觀戰時看到 `$7E:8733` 先是城 Id 63、約 1000 幀後才換成 131，推測先寫入城 Id、再由這段程式換成實際的戰場圖（未確認是同一場戰鬥）。`$C5:8330` 把 `$7E:874E` 經 `$C2:1602` 換算（推測得到戰場所在的城）後查城類，再用 `$C5:8171` 查合戦表：是合戦的城就用 111 + 合戦編號，否則依城類選無城地形圖。

## 11. 未解
