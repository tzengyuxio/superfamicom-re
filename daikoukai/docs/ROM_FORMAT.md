# スーパー大航海時代（SFC）ROM 格式

ROM：`Super Daikoukai Jidai (Japan)`，1 MB LoROM，標頭名 `SUPER DAIKOUKAIJIDAI`。
本文的「檔案位移」是去掉 copier header 後的檔案位移：CPU `$bb:8000–$FFFF` = `(bb & 0x7F) × 0x8000 + (addr − 0x8000)`。

資料與文字編碼沿用 FC 版（`~/works/famicom-re/daikoukai`）：FC 的 bank 57（初始狀態）、bank 58（名稱等資料）、
世界地圖檔都原封不動搬進 SFC ROM，表格格式相同，只是位置與圖像格式不同。

## 1. 程式結構

| 項目 | 位置 |
|------|------|
| NMI | `$00:8361`（savestate 掛在第二條指令 `$00:8362`） |
| p-code 直譯器 | 主迴圈 `$00:A141`；VM PC = `$06–$08`（長指標，程式在 WRAM bank 7E 執行），累加器 `$0A`，frame pointer `$04`，opcode 表 `$00:A797` |
| 函式 | 開頭 `20 BA 21` + 2 bytes frame 大小；呼叫 `E9 lo hi n` |
| 系統呼叫 | 服務號放 `$52`，參數從 `$54` 起；dispatcher `$00:8DDD`／`$00:8E04`，跳躍表 `$00:99F0`（檔案 0x19F0） |
| KOEI LZ | 表 0x1696，程式 `$00:97F3`，由服務 `0x4C`（`$00:9664`）包裝：`$54` = 7F bank 目的位址、`$56` 來源位址、`$58` 來源 bank。共用 `tools/koei_lz.py` |

用到的服務：

| 號 | 功能 |
|----|------|
| `03` | CGRAM DMA |
| `06` | 畫 tilemap |
| `0B` | tile DMA（起始 tile、張數、來源位址、bank） |
| `17` | 從 bank:addr 複製到 7E 記憶體 |
| `1A` | 檔案 handle seek（`$5A` 模式：0 絕對、1 相對、2 從尾端） |
| `1C` | 從 handle 讀 n bytes |
| `1D` | 從 handle 載入調色盤 |
| `1E` | 從 handle 讀 tilemap 畫到 BG（layer, x, y, w, h） |
| `4C` | LZ 解壓 |

### 1.1 檔案 handle

`$7E:1E00` 起每筆 14 bytes：+0 bank、+2 位址（LoROM，換算 `$00:9C3D`）、+4 大小、+8 目前位置（32-bit）。

| handle | 檔案位移 | 大小 | 內容 |
|--------|---------|------|------|
| `$1E00` | `0xF4FC`（`$01:F4FC`） | 0x1288 | 初始狀態（前 2 bytes 之後 = INIT） |
| `$1E0E` | `0x1423C`（`$02:C23C`） | 0xE6A8 | 圖形 tilemap 檔（TOWN_FILE），港町、選單等的 BG tilemap |
| `$1E1C` | `0x10784`（`$02:8784`） | 0x3AB8 | DATA 檔 = FC bank 58：名稱、港口、調色盤、地圖表 |

下文用「DATA + n」表示 DATA 檔內位移 n（檔案位移 0x10784 + n）。

## 2. 文字

單 byte 半形假名（JIS X0201，cp932 `$A1–$DF`），0 結尾。預設平假名；`1B 4B`（ESC K）切片假名，`1B 48`（ESC H）切回。
`$DE`／`$DF` 為濁點／半濁點，`$2D` 是長音。與 FC 版相同（`rom.text`），不需要額外字碼表，所以沒有 `data/`。

## 3. 初始遊戲狀態（INIT，檔案 0xF4FE）

新遊戲時（約 frame 2044，複製程式在 RAM `$00:006F` 執行）把檔案 0xF4FE 起 0x1286 bytes 複製到 WRAM `$7E:DF02`
（= FC `$6000`；FC `$6000+n` ↔ SFC `$DF02+n`）。

| WRAM | INIT 位移 | 內容 |
|------|-----------|------|
| `$E444` | +0x542 | 人物表 41 筆 × 7 bytes（§4） |
| `$E564` | +0x662 | 艦隊表 21 筆 × 16 bytes：bytes 0–3 = 位置（chunk x、chunk y、metatile x、metatile y，與港口記錄同格式），其餘未解（bytes 9–10 是 LE16 數值 1000／4500／5000／2000，推測為資金） |
| `$EAB0` | +0xBAE | 主角姓名（預設 レオン） |
| `$EAC0` | +0xBBE | 能力表 21 筆 × 10 bytes（§4） |
| `$EE78` | +0xF76 | 港口建物旗標 70 bytes（§7） |

開局後主角的能力由遊戲重新擲骰（命名後的確認畫面），所以能力表第 0 列只是預設值。

## 4. 人物

### 4.1 人物表（WRAM `$E444`）

第 k 筆：0 = 主角、1–20 = 航海士、21–40 = 4 國 × 5 名提督。

| byte | 內容 |
|------|------|
| 0–1 | 姓名：DATA 檔內位移（主角為 WRAM 位址 `$EAB0`）。FC 版是 `$A000` 起的 bank 58 指標，SFC 去掉了 `$A000` |
| 2 | 戰鬥等級 |
| 3 | 航海等級 |
| 4–5 | 頭像代碼（LE16，§5） |
| 6 | 旗標：高 4 bit = 國（0 ポルトガル、1 スペイン、2 トルコ、3 イギリス，推定，沿用 FC 版），bit 0 = 有效 |

### 4.2 能力表（WRAM `$EAC0`，主角＋航海士 20 人）

byte 0 年齡（推定）、1 統率、2 判断、3 知力、4 勇気、5 強さ；6–9 未解（export 以 hex 輸出）。

### 4.3 女性

DATA + 0x0C：20 個 LE16，各為姓名的 DATA 位移。第 k 位的頭像 = 專屬頭像 k + 13（推定：FC 版如此，SFC 的頭像 13–32
也正好是 20 張女性臉；遊戲內未驗證）。

## 5. 頭像

40 × 48（5 × 6 tile），4bpp，960 bytes。遊戲把 tile 放 VRAM 0x2B20、以 BG1 調色盤 5 顯示；
調色盤（CGRAM 0xA0）= DATA + 0x2070（檔案 0x127F4）32 bytes，所有頭像共用。

p-code `$7E:4EFA` 讀全域 `$7E:F295` 的代碼：≤ 0x0FFF 走 `$7E:83DE`（專屬），否則 `$7E:858D`（組合）。

### 5.1 專屬頭像 0–52

每筆 0x3C2 bytes = 2 bytes 標頭（bank 內序號 × 30）+ 960 bytes。
頭像 0–32 在 `$19:8002 + 0x3C2·n`（檔案 0xC8002），33–52 在 `$1A:8002 + 0x3C2·(n−33)`（檔案 0xD0002）。
0 = レオン、1–12 = 國王等 NPC、13–32 = 女性、33–52 = 航海士。

### 5.2 組合頭像（代碼 ≥ 0x1000，提督）

- 頭型 `head = code >> 10 & 3`；各部位頁數：上 `>> 8 & 3`、眼 `>> 6 & 3`、鼻 `>> 4 & 3`、口 `>> 2 & 3`、下 `code & 3`。
- 位址表 檔案 0xF40C：每頭型 20 個 LE16（上 ×4、眼 ×4、鼻 ×4、口 ×4、下 ×4），相對 `$1B:8000`（檔案 0xD8000）。
- tile 表 檔案 0xF4AC：每頭型 5 組 LE16（起始 tile、張數），順序同上。頭型 0：上 (0,20)、眼 (11,3)、鼻 (16,3)、口 (21,2)、下 (15,15)。
- 組合程式用服務 `17` 依「下、上、眼、鼻、口」順序把 張數 × 32 bytes 複製到 960 bytes 緩衝（WRAM `$7E:042F`）的
  起始 tile × 32 處，後者整塊 tile 覆蓋前者，再 DMA 到 VRAM 0x2B20。

## 6. 世界地圖

檔案 0x50000 = FC PRG 0x60000，逐 byte 相同：

| 位移 | 內容 |
|------|------|
| +0 | u16 chunkset 表位移、u16 chunk 資料位移 |
| +4 | 24 × 12 個區域 × 5 bytes；bytes 0–1 = chunkset 編號 |
| chunkset | 18 bytes = 9 個 LE16 chunk 編號，子位置 `(cy%3)·3 + cx%3` |
| chunk 資料 | 每 chunk 49 bytes = 7 × 7 block |

- block → 4 個 metatile（TL、TR、BL、BR）：DATA + 0x28D8 + 4·block（= FC `$BCCA`）。
- SFC 的 metatile：DATA + 0x27B0 + 8·m，4 個 LE16 BG tilemap entry（TL、TR、BL、BR），共 18 種。
  m = 0（深海，tile BF C3 C7 CB）與 m = 17（tile CF D3 D7 DB）畫在 BG2；其他陸地畫在 BG1，下面的 BG2 填 m = 0。
  DATA + 0x2840 另有一張表，用途未解。
- 全圖 72 × 36 chunk，每 chunk 14 × 14 metatile = 28 × 28 tile，共 16128 × 8064 px。
- 畫面：BG mode 1，BG1 tilemap VRAM 0xD000、BG2 0xE000（皆 doubleWidth），CHR 0x2000；一次顯示一整個 chunk，
  在 tilemap 第 2 欄、第 1 列起的 28 × 28。
- 緯度組 band = `[3,2,1,1,0,0,0,0,1,1,2,3][cy // 3]`（與 FC 相同），存 `$7E:F164`：
  - 陸地 CHR：`$10:8000 + 0x900·band`（檔案 0x80000 + 0x900·band）0x48 張，載到 tile 0x77；
  - BG 調色盤 2：DATA + 0x25B0 + 0x80·band + 0x20·frame（4 格動畫）。
- 海的 tile（0xBF–0xDE）是動畫，來源在 `$10:BEDE` 一帶（檔案 0x83EDE、0x84EDE）。`rom.SEA_CHR` 只記了出港當下
  觀察到的那一格；完整的動畫順序未解。
- 港口記號（BG1 tile 0xE8+、調色盤 3）另外蓋上，靜態圖不含。

## 7. 港口

- 港口表 DATA + 0x12D4（檔案 0x11A58）70 筆 × 19 bytes：15 bytes 名稱 + chunk x、chunk y、metatile x、metatile y。
  遊戲進港時以 handle `$1E1C` seek 到 0x12D4 + 19·port 讀取（目前港口 `$7E:EF69`）。
- 屬性 DATA + 0x1806（檔案 0x11F8A）50 筆 × 5 bytes：經濟圈、特產品（goods 編號，FF = 無）、未解、道具（推定）、未解。
- 港 50–69 是補給港，沒有屬性記錄。

### 7.1 港町圖（BG2）

SFC 版所有港口共用同一套圖（FC 版有 8 種），只有零件依建物旗標增減。tilemap 來自 TOWN_FILE（檔案 0x1423C），
每個 entry 2 bytes（SNES tilemap 格式）；每張圖在 +0xA0DA 處另有一份夜間版，畫在 y + 32（右半畫面）。

| 檔內位置 | 座標 | 大小 | 內容 |
|---------|------|------|------|
| 0x823A | (1,1) | 30 × 27 | 外框（分 8、8、8、3 列畫） |
| 0x21C2 | (2,5) | 28 × 8 | 街景上半 |
| 0x2382 | (2,13) | 28 × 7 | 街景下半 |
| 0x250A | (2,5) | 7 × 4 | 零件：旗標 bit 2 = 1 時畫（交易港） |
| 0x2632 | (23,5) | 7 × 5 | 零件：旗標 bit 4 = 1 時畫（交易港；開局只有 リスボン、セビリア、イスタンブール） |
| 0x25B2 / 0x257A / 0x2542 / 0x25EA | (2,11) / (16,5) / (9,5) / (24,13) | 7×4 / 7×4 / 7×4 / 6×6 | 交易港一律畫 |
| 0x80B2、0x800A、0x808A | (2,20)、(2,18)、(20,20) | 28×7、18×2、10×2 | 最後畫（港口） |

- 零件表在 `$06:EE2A`（檔案 0x36E2A，另一份在 0x38C80），座標比畫的位置低一列（遊戲畫在 y − 1）。補給港不畫 6 個零件。
- 旗標其餘 bit 的意義未解。
- CHR（tile 號 → 來源）：0x77–0x96 水面動畫（`$16:8B6D`，檔案 0xB0B6D，初始格）；0x97–0x153 = LZ `$16:8000` 解壓結果前
  0xBD 張；0x1A0–0x360 = `$12:8000`（檔案 0x90000）0x1C1 張。
- 調色盤：DATA + 0x1FD0 起 8 組，其中第 2、6 組改用 DATA + 0x2A70、+0x2B70。
- BG1 上的船（LZ `$16:96FB` 與其後的動態 tile）依艦隊變動，未解；BG3（文字窗）未處理。

## 9. 按鍵序列（Mesen 驗證用，`tools/boot.py`）

`w1800 start w200 a:10 w200 start:10 w200 a:10 w200 a:300 w100 down:10 w50 a:300 w100 down:10 w50 a:300 w100 a:10 w300 a:10 w300 start:10 w300 a:10 w300`
＋ 14 次 `a:10 w60 a:10 w60 a:10 w60 a:10 w60 a:10 w60`：標題 → 新遊戲 → 命名（start = 預設 レオン）→ 能力確認
→ 獎勵點數 → 船名 → 序幕（約 frame 5500 出現レオン頭像）→ 1502 年 2 月 21 日 リスボン 港町（frame 11766）。
接 `w100 down:30 w60 down:30 w60 left:30 w100` 走到港務所（frame 12236），再 `a:10 w100 a:10 w100 a:10 w700 a:10 w600`
出港，frame 13856 時海面已畫好。
