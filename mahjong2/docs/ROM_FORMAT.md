# SFC 麻雀大会II ROM 格式

KOEI，SFC。檔案 `_original/sfc/Mahjong Taikai II (Japan).zip`（No-Intro；其他版本沒有測過）。前作スーパー麻雀大会的格式見 `mahjong/docs/ROM_FORMAT.md`，本作多數機制相同，差異在各節註明。

本文的偏移一律是**檔案偏移**（無 copier header 的 1 MB 映像）。CPU 位址寫成 `$bb:aaaa`，LoROM：檔案偏移 = `(bb & 0x7F) × 0x8000 + (aaaa & 0x7FFF)`。資料串流的位址寫成 `bb:aaaa`（例如 `04:C951`），意思相同。表格幾乎都在 bank `$01`。

## 1. 硬體與引擎

| 項目 | 內容 |
|------|------|
| 標頭（`0x7FC0`） | `MAHJONG TAIKAI 2`，LoROM，ROM 1 MB，SRAM 8 KB |
| 檔案 | SHA-1 `e91bfdde475f3693a2c0d6407d8fec85bfdaf019` |
| 向量 | native NMI `$00:8050`（第一個指令是 `REP #$30`，`tools/replay.py` 自動掛在 + 2） |
| 操作 | 標題 → START → START（存檔欄，1 是新的）→ 名字：a（關提示）、a（あ）、移到おわり、a → おとこ → 臉 → 聲音 → はい → 主選單（雀荘 大会 練習／ルール ランク 成績／記録 勝利 終了）→ 雀荘 → 選雀荘 → 對手卡片選 3 人 → はい、半荘回数、レート、サシ馬 → 牌桌；牌桌上每按一次 a 就打出摸到的牌（`tools/sequences.py`） |

WRAM：`$1998` 座位 → slot，`$199E` slot → 人物（0 = 玩家），`$1A01` 目前的雀荘，`$0E02` 本局規則（44 bytes）。

## 2. 壓縮資料

KOEI LZ（`tools/koei_lz.py`，解碼表在 `0xCA04`，解壓程式 `0xCB61`）。入口 `JSL $01:8000`，位址內嵌在程式碼：

```
A9 bb        LDA #bank
F4 lo hi     PEA src         ; 串流位址
F4 .. ..     PEA dst         ; 解壓目的地
22 00 80 01  JSL $01:8000
```

用這個 byte pattern 掃整個 ROM 有 132 處呼叫。相連的串流，下一條可能從上一條回報的結尾往前最多 2 bytes 開始（找串流邊界時要注意）。頭像與台詞另有指標表（§4、§6）。

| 串流 | 內容 |
|------|------|
| `$01:CF9B` 的 26 個 3-byte 指標（`0D:AC25` …） | 對手頭像，每人一條（§4） |
| `$01:D5BE`／`$01:D5F2`（`13:CC90` …） | 對手台詞，每人一條（§6） |
| `04:C951` | 對手名字圖 26 張（§3） |
| `03:F630` | 台詞字型碼 01–D4（§6） |
| `04:AD49` | 役名的 16 × 16 字 108 個（§7） |

| 5 | 松尾芭蕉 | 12 | ホームズ | 19 | 清少納言 | 26 | シブサワ・コウ |
| 6 | 関羽 | 13 | 沖田総司 | 20 | 卑弥呼 | | |

**名字只有圖**。串流 `04:C951`：26 × 512 bytes，每人 8 × 2 個 4bpp tile（64 × 16，先上排 8 個、再下排 8 個；前作是 6 × 2），雀荘卡片上用 BG 調色盤 3。`data/persons.tsv` 是照圖抄下的名字，加上讀音與 `[EXT]出典`（不是 ROM 資料）。24–26 的名字圖在遊戲裡沒看到（只驗證了 1–23 的卡片）。

**參數**：`$01:DA92 + 12p`，p = 0–26（0 = 玩家）。`$01:C999` 開局時把四個座位的參數展開到 `$13D9 + 0x80` 以下：byte 0–10 拆成 22 個 nibble（高位在前），byte 11 拆成 8 個旗標（MSB 在前，寫成 `00`／`FF`）。和前作相同的展開方式。24–26 的 12 bytes 和 1–3 完全相同。**各值的意義未解**（`persons.csv` 的 `N00–N21`、`F0–F7` 是原始值）。

**雀荘**：`$01:D41C + p`（p = 1–23）：0 = 每個雀荘都有，k = 只在雀荘 k（固定キャラ，也是該雀荘的主人）。24–26 不在表內，只在大会出現（訊息 40「じょうい4にんさいきょうたいせん」）。雀荘 k 的對手名單 = 值為 0 或 k 的人（`$00:AF13` 建在 `$0423`，另外會去掉沒錢的人）；卡片順序是主人在前，其餘依持有金額。

|---|------|-----------|
| 0 | あなたのいえ | — |
| 1 | じゃんそう ゆう | 孔子 |
| 2 | ふじみそう | 平賀源内 |
| 3 | あおいりょかん | 水戸黄門 |
| 4 | あんこくじ | 一休 |
| 5 | ロイヤル | クレオパトラ |

## 4. 頭像

| 位址 | 內容 |
|------|------|
| `$01:CF9B` | 26 個 3-byte 指標（人物 1–26），各指向頭像串流 |
| `$02:8000 + 32k` | 調色盤 k（16 色 BGR555）；頭像只用 k = 4–8 |
| `$01:CCB1 + p − 1` | 人物 p 的頭像調色盤號（4 或 6） |
| `$01:CCCB + p − 1` | 人物 p 的 56 × 56 圖（怒）的調色盤號（多數同上；シンドバッド 5、赤ずきんちゃん 7、ジャンヌ・ダルク 8） |
| `$01:D5B0` | 7 個 LE16：表情碼 0–6 → 串流內 offset ＋ `0x1000` |

每條串流 7968 bytes，9 張圖（前作 7 張）：

| offset | 大小 | 圖 |
|--------|------|----|
| `800k`（k = 0–6） | 40 × 40（5 × 5 tile，列優先） | 0 平常、1 說話 1、2 說話 2、3 笑、4 困、5 哭、6 不滿 |
| `5600` | 56 × 56（7 × 7 tile） | 7 怒 |
| `7168` | 40 × 40 | 8 驚 |

台詞行的表情碼 0–6 對應圖 0、3、4、5、6、7、8。牌桌上整條串流解壓在 WRAM `$7F:1000`；說話臉（圖 0–2 輪播）在 VRAM `$D940`，表情圖在 `$DC60`（sprite tile `0xCA..`、`0xE3..`），調色盤載入 CGRAM 第 15 列（sprite 調色盤 7）。**表情圖與怒的調色盤要等台詞打完才換上**。`$00:C318` 讀說話的人（`$199E,Y`）。

kaodata 資料集把調色盤 4–8 併成 80 色，pixel 值 = `16 × (k − 4) + 色號`。

## 5. 規則設定

44 項，每項一個值；ルール畫面第 1 頁左欄 0–10、右欄 11–21，第 2 頁左欄 22–32、右欄 33–43。項目名稱與選項是照畫面抄的（`data/rules.tsv`；選項字是圖，未解）。

| 位址 | 內容 |
|------|------|
| `$01:D339` | 持ち点表：8 個 LE16 × 100（24,000 … 30,000，值 7 = 16,000 只有覆寫用得到） |
| `$01:D353` | 規則組 offset 表 |
| `$01:D356` | 44 bytes：各項的選項數 |
| `$01:D382` | 22 bytes：標準規則（每 byte 兩項，高 nibble 在前） |
| `$01:D398` | 7 bytes：各雀荘覆寫清單在 `$01:D39F` 的起點 |
| `$01:D39F` | （項目, 值）配對，各雀荘一段 |
| `$01:D3F1` | 13 組（A, B）：A 是 0 時 B 也設成 0（從最後一組往前套用） |

玩家的三組規則存在 SRAM，讀到 WRAM `$192F`（每組 22 bytes，用第 0 組）。開局時 `$01:8F8A` 把玩家的規則組載入 `$0E02`，雀荘 1 改用標準規則，其他雀荘套上自己的覆寫，最後套前提關係。

| 雀荘 | 固定規則 |
|------|----------|
| あなたのいえ | 無（用玩家的規則） |
| じゃんそう ゆう | 標準規則 |
| ふじみそう | ドボン 無、持ち点 24,000、馬 10-30、焼き鳥 無、ワレ目 無、チップ 無 |
| あおいりょかん | ドボン 30、持ち点 16,000、西入 無、場風 東東 |
| あんこくじ | 二飜縛り 有 |
| ロイヤル | 連荘 聴牌、裏ドラ・槓ドラ・槓裏・一発 有、ドボン 30、持ち点 24,000、場風 東南、馬 10-30、焼き鳥 裏20、ワレ目 有、チップ・一発賞・裏ドラ賞・役満賞・鳥撃ち・アリス・完全麻雀 有 |
| じゃんそう はぎ | 連荘 和了、場風 東風、馬 10-20、焼き鳥 10、チップ 有、鳥撃ち 有 |

（完整的值見 `rules.csv`、`parlors.csv`。）13 組前提關係：裏ドラ → 槓裏、裏ドラ賞；槓ドラ → 槓裏；一発 → 一発賞；場風 → 西入、完全麻雀；チップ → 一発賞、裏ドラ賞、役満賞、鳥撃ち、アリス、完全麻雀；二家和 → 三家和（`rules.csv` 的「前提項目」欄）。

## 6. 台詞與字型

**台詞串流**：位址低 16 位 `$01:D5BE`（26 個 LE16）、bank `$01:D5F2`（26 bytes）。每人 344 行 × 25 bytes：byte 0 = 表情碼（§4），byte 1–24 = 24 個字碼（3 行 × 8 字；前作 2 × 8）。說話時整條解壓到 `$7F:6000`；要顯示的那行複製到 `$0EB1–$0EC9`（24 個字碼倒序存放，`$0EC9` 是表情碼），`$00:C366` 之後畫出。

**情境**：103 個，三個表：

| 位址 | 內容 |
|------|------|
| `$01:D60C` | 104 個 LE16：各情境的第一行，最後一個值是 344 |
| `$01:D6DA` | 103 bytes：n，說哪一行 = 第一行 + random(n)；超過下一個情境的第一行就不說話 |
| `$01:D741` | 103 bytes：旗標（`00`、`20`、`80`、`C0`） |

情境 92（`0x5C`）在程式裡另外處理。所有對手共用同一套情境與行號。**情境的意義未解**（`situations.csv` 附リンカーン與卑弥呼的第一行）。

**字型**：串流 `03:F630`，碼 01–D4 各 64 bytes（8 × 16，上下兩個 4bpp tile，碼 c 在 `64 × (c − 1)`）。碼 c 畫成 BG tile `0x56 + 2c`（下半 `+1`），調色盤 3。字碼和前作相同（00–D3），只有 `0D` 是 G（金額單位）；`D4` 是空白，實際畫成 tile `0x06E`。對照在 `data/charset.txt`，沒有漢字。

## 7. 役名

## 8. 系統訊息

`$01:DDFC` 起，以 `00` 分隔，71 則（1 起算）。每則開頭是標頭：第一個 byte 的 bit 7 為 1 時標頭 6 bytes，否則 4 + 2 × bit0 + 2 × bit1 bytes（位置、大小等，細節未解），之後是字碼（§6）；`D5` 換行、`DA` 換頁，`D6`–`D9` 是選項與數值（`messages.csv` 寫成 `[D8]` 等）。`$00:918A` 依編號找訊息、位址存 DP `$58`；`$00:938B` 回傳標頭長度（存 `$0D9E`）。

| 編號 | 內容 |
|------|------|
| 1–11 | 存檔、名字、性別、臉、聲音、規則組 |
| 12–15 | 練習模式、リプレイ、對手強度、雀荘選擇 |
| 16–22 | 雀荘 0–6 的說明 |
| 23–30 | 選對手、半荘回数、サシウマ |
| 31–37 | 大会：說明、予選（8 人通過）、決勝トーナメント、決勝戦 |
| 38–40 | 最強対戦：持有金額前 4 名，依名次有讓分 |
| 41–47 | 最終対戦：3 人（24–26）的台詞與規則（4 半荘總分） |
| 48 | 空（人物 0） |
| 49–71 | 人物 1–23 的紹介（訊息 48 + p） |

## 10. 未解

- **對手參數**（`$01:DA92`）22 個 nibble 與 8 個旗標的意義（打牌風格）。
- **情境**的意義與 `$01:D741` 旗標；情境 92 的特別處理。
- **飜數表**：役 → 飜數的表沒找到（`$1769` 由和牌判定寫入）。
- **大会**：予選的組合、決勝トーナメント、最強対戦的讓分與最終対戦（24–26）的進行，只從訊息 31–47 知道流程，資料表未解。
- **ランク／成績／記録／勝利**畫面與 SRAM 內容（持有金額 `$19D1`，100／200G 單位等）。
- **玩家頭像**（可選 3 種）的位置。
- 24–26 的名字圖在遊戲中沒看到。
- **規則選項字**：ルール畫面的字是圖，`data/rules.tsv` 是照畫面抄的。
- 訊息標頭各 byte 的意義；71 則之後是否還有訊息。
- あんこくじ（二飜縛り）與積み棒相關的判定（`$01:8FF6` 之後）。
- 雀荘畫面的圖與名稱的來源。
- 其他版本（Rev）沒有比對。
