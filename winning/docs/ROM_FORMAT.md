# SFC ウイニングポスト ROM 格式

位址寫法：`$BB:AAAA` 是 CPU 位址（HiROM），「ROM 0x……」是檔案偏移，`ROM = $BB:AAAA & 0x3FFFFF`。WRAM 位址 `$xxxx` 都在 `$7E`。以下偏移是原版；Rev 1 的差異見 §11。

## 1. 硬體與引擎

- 2 MB HiROM，無 header（`$FFDB` = 0 原版、1 Rev 1）。程式是 C 編譯的原生 65816 程式；函式用堆疊傳參數，區域變數放堆疊（`$xx,S`），回傳值在 DP `$00–$02`。
- 圖形是 KOEI LZ（共用 `tools/koei_lz.py`）：表在 ROM `0x9F53`，指標表 ROM `0x1C961`（3-byte × 769）。
- 文字輸出：vprintf `$C2:1E9A`（S+4 = 格式指標 3 bytes、S+8 = va 指標，bank 0）；`%s` 的引數是 4-byte 指標（最高 byte 不用），另有 `%y`（數字）、`%2d`、`%p`、`%h` 等；puts `$C2:06E9`（S+4 = 字串指標）。驗證腳本 hook 這兩處記錄遊戲印出的字（`tools/wp.py` 的 `PRINT_LUA`）。
- 記憶體複製 `$C1:3379(dst24, src24, len)`（在 WRAM `$DE43` 跑 MVN）；乘法 `$C1:F013`、陣列索引 `$C1:F4E9`（乘）／`$C1:F501`（左移）、比較 `$C1:F432`（`$04 < $00` → 1）。

## 2. 字型與文字編碼

- 全形字：2-byte 碼 `0x8140 + g`，字形 g 每字 32 bytes（四個 1bpp 8×8 tile，左上、右上、左下、右下）。`g < 0x400` 在 `$C0:0000 + 32g`，其餘在 `$DF:(32g − 0x4000)`（16 位元運算，`$DF:4000–$DF:E7E0`）。共 2368 字（`data/charset.txt`）：0–232 記號、全形數字與英文、平假名、片假名、①–⑫、ⅠⅡⅢⅥ；233–2323 JIS 第一水準漢字的子集（JIS 順序）；2324–2349 第二水準人名用字；2350– ㊛㊚〓（圈牝／牡／騸）、第回（）ＧＩ歳上ｍ¼½¾■ 等。
- 字形查詢 `$C2:0E5D`：碼 > `0x8A7F` 時，`0x9140 + k` → `0x8200 + 0x100k`（`91 xx` 是「低位 byte 為 00 的字」的跳脫），其他 → `0x8140`（空白）。`rom.glyph_code`／`glyph_offset`。
- 單 byte：半形假名（cp932 `0xA6–0xDF`），預設**顯示成平假名**；`1B 4B` 切成片假名、`1B 48` 切回平假名；濁點／半濁點是另一個 byte（`ﾀﾞ`），解碼時要合成（rom.py 做 NFC，否則得到「た + U+3099」，看起來一樣但比對不相等）；`1B 43 n` 顏色；`0x0A` 換行；`0` 結束。8×16 半形字走另一條路（未追）。
- 字表是用遊戲字形與系統字型做單調 DP 比對再目視修正（塘→塔、椀→碗、隣鱗→鱗麟、篭→籠 等），比對圖不進版控；遊戲中確認過的字見各驗證腳本。

## 3. 人名表

- 姓 `$C1:921D`、名 `$C1:881D`：各 256 個 3-byte 指標，字串以全形空白補齊。0–4 竹川雄二／石田茂／小野あかね／結城新吾／黒木幸恵（劇情人物），5–14 外國騎手（姓是半形片假名，長音用 ASCII `-`；名是全形縮寫），15– 日本騎手與其他。
- 馬名編碼（1 byte 一字）：`0xAE–0xE5` = 半形假名 `0xA6–0xDD`（+8）；`0xE6–` = ガギグゲゴザジズゼゾダヂヅデドバビブベボパピプペポヴ；`0x2D` = ー；`0x20` 空白。

## 5. 馬

馬 ID（`$C5:6040`）：0–399 現役馬、400–569 繁殖牝馬（ID − 400）、570– 種牡馬（ID − 570）。種牡馬與牝馬的父母欄有大於 640 的值（例：ノーザンテースト 744 × 1380），指向的血統表未找到（未解）。

### 5.1 現役馬（37 bytes）

`+0` 馬名 word（§5.4）、`+2` 父 ID、`+4` 母 ID、`+6..36` 未解（與 DOS 版 `HORSE.CIM` B 段 `+0x0d` 之後的欄位同一套，能力值、成績等）。空槽 `+0 = A4DF`、父母 FFFF。0–29 空槽，381 筆有效。

### 5.2 種牡馬（19 bytes）、5.3 繁殖牝馬（20 bytes）

都是 `+0` 馬名 word、`+2`／`+4` 父母 ID（牝馬的父多是種牡馬 ID：ダイナアクトレス 570 = ノーザンテースト），其餘未解。種牡馬 50 筆有效（ノーザンテースト…イブキマイカグラ），50–69 空槽（名字 0、父母 FFFF）。

### 5.4 馬名 word（`$C5:5D4E`）

`k = w >> 10`、`n = w & 0x3FF`，回傳字串指標（DP `$00`；合成的名字放 WRAM `$E81A`）：

| k | 名字 |
|---|------|
| 0–39 | 馬主 k 的冠名（5 字）＋範本 n（9 字），合計截到 9 字；馬主記錄 `+2 & 3 == 2` 時範本在前、冠名在後；`n > 0x315` 只用範本 |
| 0x28 | 玩家取的名字 WRAM `$A75E + 9n` |
| 0x29 | 固定名 `$CF:D92F + 9n`（605 筆：スピードシンボリ、メジロムサシ…，種牡馬、牝馬與特別馬的名字） |
| 0x2A | 外國馬名 `$C1:BA9D + 11n`（100 筆，kana[9] + u16；= DOS `GNAMESMP.CIM`） |
| 0x2B | 固定名 0（空字串），並印出除錯訊息 `S1(%d)don't have code in get-cod`（`$C5:C2AA`） |
| 0x2C | 範本 `(n >> 5) + 0x2DE` 接範本 `n & 31`，截到 9 字 |
| 0x2D– | 固定名 0（空字串） |

名字範本 `$C1:9A45`：828 × 10（kana[9] + 旗標 u8，= DOS `UNAMESMP.CIM`），旗標意義未解。

## 6. 人物記錄

### 6.1 馬主（`$CF:D0C2`，41 × 24）

`+0` 頭像碼 u16（全部是組合臉，§8.2；和 DOS 版相同）、`+2` 旗標（bits 0–1 = 2：冠名放在範本後；其餘未解）、`+3..4` 未解、`+5` 姓 7 bytes、`+12` 名 7 bytes、`+19` 冠名 5 bytes（馬名編碼）。40 是玩家（「ユーザ①」，頭像碼 0）。SFC 版的姓有截短（大和田 → 大和）。

### 6.2 調教師（`$CF:D49A`，30 × 22）

`+0` 頭像碼 u16（0–29）、`+2` 所屬騎手（騎手 20 + 此值）、`+3..4` 未解、`+5` 性格旗標、`+6..7` 未解、`+8` 姓 7 bytes、`+15` 名 7 bytes。資訊視窗 `$CB:77C2` 依 `+5` bits 0–5 選字（bit = 0／1）：

| bit | 項目 | 0 | 1 |
|-----|------|---|---|
| 0 | 性格 | 短気 | 冷静 |
| 1 | 方針 | 現実主義 | 理想主義 |
| 2 | 連闘 | たまにする | 滅多にしない |
| 3 | 騎手起用 | 専属騎手優先 | こだわらない |
| 4 | 調教 | 慎重 | スパルタ |
| 5 | 相手比較 | 慎重 | 強気 |

### 6.3 騎手（22 bytes；0–19 在 `$CF:D777`，20–69 在 `$CF:BF24`）

`+0` 頭像碼 u16、`+2` u16（外國騎手全是 40000）、`+4..6` 3 個值（推測能力）、`+7..14` 0（推測當年成績）、`+15`、`+16`、`+17`（值 19–62，推測年齡）、`+18` u16（日本騎手 8–973，推測通算勝數）、`+20`、`+21` 人名號（兩者相同；名字由 `+21` 查 §3）。0–9 外國騎手（モトリー Ｐ…）、10–19 日本騎手（笹竹満夫…）、20–69 日本騎手（岡路幸夫…）。除了頭像碼與人名號，欄位意義都是推測（未驗證）。

## 7. 比賽

- 比賽名 `$C5:DAA3`：232 個 3-byte 指標。0–85 重賞（ＧⅠ–ＧⅢ，0 日本ダービー、1 天皇賞・春…），86–191 OP 與特別戰，192–231 不在日程裡（192 凱旋門賞…231 サラブレッドＣＣ，海外與特殊比賽）。
- 第 N 回 `$CA:D742`：86 × u16，重賞 r 在 1997 年的回數；遊戲印 `CA:D742[r] + (年 − 1997)`。非重賞印 FFFF（不顯示）。
- 日程 `$CF:41C6`：384 × 4 bytes（第 385 筆是別的資料）。格 i：月 `i / 32 + 1`、週 `i % 32 / 8 + 1`、該週第 `i % 8 / 2` 場、`i % 2` = 0 東／1 西。
  - b0：比賽號（0xFF = 一般戰，無名）
  - b1：`距離 << 4 | 性別 << 2 | 年齡`；距離 `$CB:E20A`（12 bytes × 100 m：1000 1200 1400 1600 1800 2000 2200 2400 2500 3000 3200 3600）、年齡 `$CB:E1D0`（３歳／４歳／４歳上／５歳上）、性別 `$CB:E1F4`（無／招／牡／牝）
  - b2、b3：未解（b3 可能是斤量條件）
- 等級 `$CD:7DE9`：385 × u16，低 4 bits → `$CB:E0C1` 短名（ＧⅠ ＧⅡ ＧⅢ ＯＰ ９特 ９下 ５特 ５下 新馬 未勝）／`$CB:E111` 長名（…900万特 900万下 500万特 500万下 新馬 未勝利）；高位（0、2、4）未解。
- 開催 `$C1:C0DF`：12 月 × (東, 西)，`回 << 4 | 競馬場`；週刊頁用**目前的月**（`$7E:DA63`）查。
- 競馬場 `$C1:C1CF`：6 bytes × 8：旗標、名稱 2 字、0。0 東京、1 中山、2 福島、3 新潟、4 京都、5 阪神、6 中京、7 小倉（沒有札幌、函館）；旗標意義未解。
- 重賞頁 `$C8:5258(x, y, 格)`：puts 比賽名（`$C5:AE9E`）、`第%y回`（`$C8:C41C`）、等級（`$C5:A80D`）、`%y回%s%y週`（`$C8:C42C`）、`%2d00m %s %s`（`$C8:C437`）。
- `$CB:E216` 12 × u16（500 600 750 850 1000 1100 1250 1350 1450 1800 1900 2150）：推測賞金，未解。

## 8. 頭像

40 × 48 = 5 × 6 個 4bpp tile（逐列），960 bytes。繪製 `$CA:2DA7(…, 碼 S+$44, 槽 S+$46)`：tile 經 `$7F:8F00` 送到 VRAM（槽 0 在 `$85C0`），調色盤直接從 ROM DMA 到 CGRAM 第 2 列（DMA 來源是 ROM，所以讀取追蹤抓不到）。調教師清單不經過 `$CA:2DA7`：清單頁把該頁 8 位調教師的頭像（記錄 `+0`）依列放到 VRAM `$A800 + 0x3C0 × 列`，資訊視窗沿用清單載入的頭像。用 ROM patch 把清單第一列換成 0x28 以上的碼時，VRAM 不會是那張肖像（0x30 只寫了一部分、0xB0 留著原本的 0），只有調教師的碼 0x00–0x27 會正確顯示。

### 8.1 肖像（碼 0x00–0xCF）

LZ entry 287 + 碼。調色盤依碼的範圍（`$CA:2DA7`）：

| 碼 | 內容 | 調色盤 |
|----|------|--------|
| 0x00–0x27 | 西裝（調教師用 0x00–0x1D） | `$C1:DFC3` |
| 0x28–0x9D | 騎手 | `$C1:DF83` |
| 0x9E–0xA7 | 騎手（女性等） | `$C1:DFA3` |
| 0xA8–0xB5 | 外國騎手 | `$C1:DFE3` |
| 0xB6–0xC4 | 不戴帽的年輕臉（用途未解） | `$C1:DFA3` |
| 0xC5–0xCE | 西裝的年長者（用途未解） | `$C1:DFC3` |
| 0xCF | 秘書 有馬桜子 | `$C1:DFA3` |

### 8.2 組合臉（碼 ≥ 0xD0，資料裡都是 bit 15 = 1）

`$CA:223A`：類型 t = bits 14–12，四個 2-bit 零件 p0 = bits 1–0、p1 = bits 3–2、p2 = bits 5–4、p3 = bits 9–8（bits 6–7、10–11 不用）。零件圖：`$C1:CF2E[t]`（3-byte 指標，LZ entry 495–502）解出 3840 bytes = 4 張臉 × 30 tile。合成：

1. tile 0–14 ← 零件圖第 p0 張的 tile 0–14；
2. tile 15–29 ← 第 p1 張的 tile 15–29；
3. 兩段 ← 第 p2 張，兩段 ← 第 p3 張：起點 `$CA:E566[t][j]`、長度 `$CA:E586[t][j]`（j = 0, 1 用 p2，2, 3 用 p3；長度 0 跳過）：

| t | 起點 | 長度 |
|---|------|------|
| 0 | 6 11 16 21 | 3 3 3 3 |
| 1 | 5 10 15 20 | 4 4 4 4 |
| 2 | 6 11 16 21 | 4 4 3 3 |
| 3 | 11 16 21 0 | 4 4 3 0 |
| 4 | 11 16 21 0 | 3 3 3 0 |
| 5–7 | 11 0 16 21 | 3 0 3 3 |

調色盤 t < 4 用 `$C1:DF43`，否則 `$C1:DF63`。

## 9. 名稱表（bank `$CB`，3-byte 指標表）

`$CB:DE45` A／B／C／ユーザー、`$CB:DEDF` 距離適性 5（スプリンター…万能）、`$CB:DF26` 毛色 8（鹿毛…芦毛）、`$CB:DF79` 白斑 16（無白、星、流星…）、`$CB:E02B` 腳白 3（長白／白／微白）、`$CB:E041` 腳 4（左前…右後）、`$CB:E061` 產地 8（早来専売…十勝専売）。調教師資訊視窗的格式與選項字串在 `$CB:EF1D–F014`。馬記錄裡對應這些表的欄位未找。

## 10. 操作序列（驗證用，幀數從開機算；`tools/wp.py`）

- 第 6300 幀左右按 START，下、A 選「ゲームを最初からやりなおす」，A × 5（每次等 300 幀）；之後每次 `a:10 w200`：秘書介紹、拠点（関東）、名字（連按 A → あああ）、性別／年齡／血型／稱呼、4 歲馬（5 匹選 1，取名 A × 9 → アアアアアアアアア）、3 歲馬（先 right 再 A × 9 → イイイイイイイイイ，否則「その馬名はすでに使用」）。第 37 次按 A 後遊戲會把名字和所有馬比對（`$C5:5D4E` 約 1500 次）。
- `TRAINER_LIST`（20660）：第 1 次 A 出秘書的確認、第 2 次進調教師清單、第 3 次開第一位（奥山）的資訊視窗；奥山拒絕（見知らぬ人の馬はちょっと…）。清單裡的第一次 right 要先看過一次資訊視窗才有效。選松岡 → 1997 年 1 月，松岡來訪，月刊競馬ニュース（騎手／調教師／馬主／生產者／預想家排行，接著「1月の重賞」每頁一場）。
- 名字比對：在 16660 存 savestate 再按一次 A，replay 裡不會觸發（原因未查）；`verify_horses.py` 改在 16430 存、按 3 次。

## 11. Rev 1

程式大量位移（每個 bank 都有差異），資料表多數不動：bank `$CF` 的記錄（馬、人物、日程、固定名）位置不變；`$C1`、`$C5`、`$CA`、`$CB` 的表位移 0x2E–0x61（`rom.REV1`，以內容搜尋對齊）。解碼結果與原版相同，只有外國馬名表在 55 插入「スクランブル」（原版 55 起各往後移一格，最後的「シッド」被擠出）。驗證腳本的 hook 位址都是原版的。

## 12. 未解

- 現役馬 37 bytes 的 `+6` 之後、種牡馬／牝馬的 `+6` 之後（能力、成績、毛色等），以及大於 640 的父母 ID 指向的血統表。
- 騎手記錄的資料欄（§6.3 的推測都沒驗證）、馬主 `+2..4`、調教師 `+3..4`、`+6..7`。
- 初始資料多數區塊（§4 標「未解」者）、日程 b2／b3、等級 word 的高位、競馬場旗標、`$CB:E216`。
